# FG Studio 私人 AI 创作台设计规格

> 日期：2026-07-15  
> 状态：产品、视觉、数据、模型、计费与验收方向已获用户逐段确认；待文档复核后进入实施计划  
> 部署链路：GitHub `loy27felix/fgai-app` → Vercel → Supabase

## 1. 背景

FG Studio 当前以“导演项目”为核心，用户必须进入项目后才能使用故事圣经、剧本、资产、导演分镜、逐镜头设计、视频和 BGM 等七阶段工作流。现有聊天、画布、资产和生成接口也以 `project_id` 和项目成员权限为边界。

新需求是增加一个与“导演台”平级的“AI 创作台”，服务不需要导演项目的用户。用户登录后自动拥有私人创作空间，可以直接：

- 与文本或多模态模型对话；
- 在独立界面生成图片；
- 在独立界面或节点画布生成视频；
- 管理会话、文件夹、画布和生成结果；
- 复用 FG Studio 已有 Skills 和 Prompt 模板；
- 在需要时把生成结果发送到导演项目，但导演项目不是前置条件。

本设计以“只增加功能，不改变现有导演台界面和工作流”为硬约束。

## 2. 目标与非目标

### 2.1 目标

1. 登录后提供“AI 创作台”和“导演台”两个同级工作区入口。
2. 为每个用户自动创建一个私人创作空间，不创建隐藏导演项目。
3. 提供三个清晰、独立的一级入口：对话、生图、生视频。
4. 图片和视频同时支持对话辅助和画布工作流；视频默认进入节点画布。
5. 媒体生成必须经过明确二次确认，避免自然语言对话意外消耗额度。
6. 接入已确认的 DeepSeek、Wetoken 文本、图片和 Seedance 视频模型，并允许用户自行选择。
7. 记录每位用户的 Token、图片/视频用量和金额，提供管理后台统计。
8. 保持已有导演项目数据、路由、视觉和七阶段工作流兼容。

### 2.2 非目标

- 不重做或替换现有导演台、项目列表和七阶段工作台。
- 不把私人创作空间伪装成项目，也不要求用户先创建项目。
- 不实现视频拼接、时间线剪辑或最终成片导出。
- 不允许聊天模型自行调用媒体生成接口。
- 不在浏览器、数据库或日志中暴露供应商 Key。
- 不在本轮升级 Next.js、React 或 Supabase 客户端的大版本。

## 3. 产品信息架构

登录后的工作区层级采用已批准的“双工作台门户”方案：

```text
FG Studio
├── AI 创作台（私人空间，不依赖项目）
│   ├── 对话
│   ├── 生图
│   │   ├── 独立生图
│   │   └── 图片画布
│   ├── 生视频
│   │   ├── 视频画布（默认）
│   │   └── 对话式 Prompt 准备
│   ├── 文件夹 / 会话历史
│   ├── 私人素材
│   └── Skills / Prompt 模板
└── 导演台（现有功能保持原样）
    └── 现有项目与七阶段工作流
```

私人创作结果默认保留在 AI 创作台。只有用户主动选择“发送到导演项目”时，系统才检查目标项目权限并复制素材。

## 4. 视觉与交互原则

### 4.1 保持 FG Studio 视觉系统

新页面复用当前 `fg2` 设计令牌和交互组件：

- 蓝紫深色渐变背景；
- `#74f08e` 绿色强调色与 `#9db4ff` 辅助色；
- Space Grotesk、Noto Sans SC 和 JetBrains Mono 字体；
- 当前玻璃面板、细描边、圆角、阴影和动效曲线；
- 当前顶部栏、FG 标识、头像、保存状态和明暗主题逻辑。

现有页面不做视觉重构。唯一与旧界面相关的改动是增加进入 AI 创作台的同级入口。

### 4.2 对话页

对话页借鉴 ChatGPT 和 Claude 的信息层级，但不复制其品牌视觉：

- 采用单一居中阅读列，不常驻右侧检查器；
- 助手消息以正文为主，避免每条消息都变成厚重卡片；
- 用户消息使用轻量气泡；
- 输入器固定在内容区底部，容纳上传、Skill、Prompt、模式和模型选择；
- 生成草稿卡嵌入对话流，显示 Prompt、模型、尺寸、数量、预计消耗和确认按钮；
- 未确认前允许继续对话修改草稿。

### 4.3 独立生图页

- 独立入口，不要求先开对话。
- 提供 Prompt、参考图、模型、比例、质量和数量设置。
- 显示最近生成的私人图片。
- 提供“独立生图 / 图片画布”切换。
- 点击“确认生成”前不创建供应商请求。

### 4.4 生视频画布

视频默认进入沉浸式无限画布，交互参考 TapNow 的节点工作流：

- 文本 Prompt 节点；
- 图片参考节点；
- 视频参考节点；
- 音频参考节点；
- 视频生成节点；
- 连线决定视频节点的输入来源；
- 选中节点时才显示参数检查器；
- 生成节点显示模型、时长、比例、分辨率、音频和任务状态；
- 每个生成节点单独确认和运行。

## 5. 私人空间数据设计

为最大限度隔离旧导演项目逻辑，新功能使用独立的 `creator_*` 表，不把现有项目表的 `project_id` 改成可空，也不改变旧表既有 RLS 语义。

### 5.1 `creator_workspaces`

每位用户恰好拥有一个私人空间。

| 字段 | 说明 |
|---|---|
| `id` | 私人空间 UUID |
| `owner_id` | Supabase Auth 用户，唯一 |
| `name` | 默认“我的创作空间” |
| `settings` | 默认模型、界面偏好等 JSONB |
| `created_at/updated_at` | 时间 |

首次访问 AI 创作台时以幂等方式自动创建；不能因刷新页面创建多个空间。

### 5.2 `creator_folders`

保存会话文件夹，支持同一工作区内排序、重命名和归档。

### 5.3 `creator_sessions` 与 `creator_messages`

- 会话保存 `chat/image/video` 类型、标题、文件夹、默认模型和更新时间。
- 消息使用独立行保存，而不是把整个会话覆盖成一段 JSON。
- 消息内容支持文本、附件引用、工具结果、生成草稿和错误状态。
- 生成草稿只保存结构化参数，不包含 Key、完整 base64 或敏感响应头。

### 5.4 `creator_canvases`

- `kind` 为 `image` 或 `video`；
- `graph` 保存节点、连线、视口和轻量 UI 状态；
- `version` 用于乐观并发和防止旧页面覆盖新数据；
- 画布归属于私人空间，可选择关联会话或文件夹。

### 5.5 `creator_assets`

保存上传素材和生成结果：

- `kind`: `image/video/audio/document`；
- `source`: `upload/generation/project_copy`；
- 私有 Storage path、mime type、尺寸、时长和缩略图；
- Prompt、模型、生成任务和来源资产引用；
- 可选的目标导演项目复制记录。

### 5.6 `creator_generation_tasks`

统一记录图片和视频生成生命周期：

```text
draft → submitting → queued → running → succeeded
                              └──────→ failed
submitting → unknown
```

主要字段：

- 用户、工作区、会话、画布和节点 ID；
- `kind/provider/model`；
- 清理后的请求参数；
- 外部任务 ID 和内部幂等键；
- 状态、输出、错误、确认时间和完成时间；
- 是否为 Filter-off；
- 对应的用量流水 ID。

## 6. 权限与 Storage

### 6.1 RLS

- 普通用户只可读写 `owner_id = auth.uid()` 的私人空间及其下级数据。
- 管理员统计通过服务端受控查询或受保护的聚合 RPC 获取。
- 浏览器不能通过传入他人的 workspace、session、canvas、asset 或 task ID 绕过权限。
- “发送到导演项目”还必须通过现有项目成员权限检查。

### 6.2 私人素材桶

- 新建私有桶，例如 `creator-assets`；
- 客户端通过短时签名 URL 查看素材；
- 存储路径包含 `owner_id/workspace_id/...`；
- 上传和下载都验证对象归属；
- 不改变现有 `project-assets` 的历史路径和行为。

## 7. 模型目录

### 7.1 对话模型

| 模型 | Provider | 界面定位 |
|---|---|---|
| DeepSeek v4 Flash | DeepSeek | 保留、快速 |
| DeepSeek v4 Pro | DeepSeek | 保留、强推理 |
| `gpt-5.6-luna` | Wetoken | 默认、快速 |
| `gpt-5.6-terra` | Wetoken | 均衡 |
| `gpt-5.6-sol` | Wetoken | 高级推理 |
| `claude-opus-4-8` | Wetoken | 高级多模态 |

### 7.2 图片模型

| 模型 | 状态 |
|---|---|
| `gpt-image-2` | 默认 |
| `gemini-3-pro-image-preview` | 正常可选 |
| `gemini-3.1-flash-image-preview` | 实验 |
| `gemini-3.1-flash-lite-image` | 实验 |

实验模型正常显示并允许选择，但不作为默认值。服务端必须拒绝不支持的参数，不能静默改用其他模型。

### 7.3 视频模型

| 模型 | 分组 |
|---|---|
| `doubao-seedance-2-0` | 标准、默认 |
| `doubao-seedance-2-0-fast` | 快速 |
| `dreamina-seedance-2-0-mini` | 轻量 |
| `doubao-seedance-2-0-filter-off` | 高级 / Filter-off |
| `doubao-seedance-2-0-fast-filter-off` | 高级 / 快速 / Filter-off |
| `dreamina-seedance-2-0-mini-filter-off` | 高级 / 轻量 / Filter-off |

Filter-off 模型全部接入。选择时提示过滤策略较弱或关闭，但提示不阻止用户继续。提示不代表允许违反平台规则或适用法律。

## 8. API 分层

旧 `/api/ai/*` 项目接口保持兼容。私人创作台使用独立路由：

- `GET/POST /api/creator/workspace`
- `GET/POST/PATCH /api/creator/folders`
- `GET/POST/PATCH /api/creator/sessions`
- `POST /api/creator/chat`
- `GET/POST/PATCH /api/creator/canvases`
- `GET/POST /api/creator/assets`
- `POST /api/creator/generations/drafts`
- `POST /api/creator/generations/[id]/confirm`
- `GET /api/creator/generations/[id]`
- `POST /api/creator/generations/[id]/retry`
- `POST /api/creator/assets/[id]/send-to-project`
- 管理员用量与导出接口。

Route Handler 只负责认证、校验、事务和响应映射。模型调用复用 `lib/ai` 中已有的文本、图片和视频适配器。

## 9. 媒体生成确认协议

### 9.1 对话不能直接生成媒体

`/api/creator/chat` 只能调用文本模型。模型可以返回结构化 `generation_draft`，但没有访问图片或视频 Provider 的工具权限。

### 9.2 确认接口

1. 用户或画布先创建 `draft`；
2. 界面显示最终 Prompt、模型、参数和预计用量；
3. 用户点击确认；
4. 服务端在事务中验证草稿归属和状态；
5. 生成内部幂等键并把状态改为 `submitting`；
6. 才调用供应商；
7. 保存外部任务 ID、状态和计费信息。

重复点击、刷新、网络重试和前端超时都必须复用同一任务，不能产生第二次生成。

### 9.3 重试

- 图片或视频失败后不自动重新提交；
- “重新生成”需要新的确认；
- 查询任务状态不算新生成；
- 供应商响应不明确时标记 `unknown`，交由用户或管理员核实，不自动重发；
- 生成成功但 Storage 转存失败时只重试转存。

## 10. 用户用量与金额统计

新增统一的 `ai_usage_ledger`，覆盖导演项目和私人创作台的新调用。旧 `ai_usage` 可保留兼容，实施时通过双写或迁移视图逐步切换。

### 10.1 流水字段

- `user_id`、workspace/project ID；
- 请求和供应商请求 ID；
- 文本、图片或视频类型；
- Provider 和精确模型名；
- 输入、输出和总 Token；
- 图片数量、尺寸、质量；
- 视频时长、分辨率、音频选项；
- 输入/输出计算单元；
- 供应商实报金额；
- 本地估算金额；
- 币种；
- `reported/estimated/unknown` 计费来源；
- 调用状态和是否可能已扣费；
- 调用时的价格快照 JSON；
- 创建、确认和完成时间。

金额使用数据库 `numeric`，不使用浮点数。

### 10.2 价格与准确性

- Provider 返回明确费用时，后台显示“供应商实报”；
- 只返回 Token、计算单元或任务参数时，使用版本化价格表估算；
- 每次调用保存当时价格快照，历史金额不随未来价格变化；
- 不能从全账户余额差值反推单用户费用，因为并发调用会导致错误归因；
- 实报和估算不得在后台混成一个没有说明的“准确账单”。

### 10.3 管理后台

后台增加：

- 今天、近 7 天、本月总花费；
- 每用户调用次数、Token、图片张数、视频时长和金额；
- 按模型、Provider、媒体类型拆分；
- 最贵用户和任务；
- 实报、估算和未知金额占比；
- 日期、用户、模型和状态筛选；
- CSV 导出；
- 可选的每日/月度用户额度和超额提醒。

## 11. 发送到导演项目

此操作始终是显式、可选操作：

1. 用户选择私人素材和目标项目；
2. 服务端检查项目成员及编辑权限；
3. 把文件复制到现有 `project-assets` 路径；
4. 创建现有 `assets` 记录并保存来源元数据；
5. 私人素材原件继续保留；
6. 操作失败时回滚项目记录或清理不完整副本，不删除原件。

## 12. 故障与恢复

- Provider 调用前必须先存在本地任务，避免完全不可追踪的外部任务。
- Provider 已接收但本地更新失败时，保留内部请求 ID并进入可核查状态。
- 所有错误响应去除 Key、Authorization、完整上游 Header 和原始 base64。
- 外部视频 URL 成功后尽快归档到私有 Storage；归档失败不触发重新生成。
- 任务轮询采用退避策略，完成、失败或过期后停止。
- 后台提供按外部任务 ID 查询和人工核对入口。

## 13. 测试与验收

### 13.1 自动测试

- 模型目录包含所有指定模型、实验和 Filter-off 标记；
- 自动创建私人空间具有幂等性；
- RLS 阻止跨用户读取会话、画布、素材、任务和账单；
- 聊天生成草稿时媒体 Provider 调用次数为零；
- 草稿确认恰好调用一次 Provider；
- 重复确认复用同一任务；
- Provider 超时或结果不明确时不会自动重发；
- Storage 转存失败只重试转存；
- 用量流水正确归属用户和空间；
- reported 与 estimated 金额正确区分；
- 价格快照保证历史金额稳定；
- 发送到导演项目执行权限检查并保留私人原件。

### 13.2 回归与线上验证

- 现有测试全部通过；
- `npm test` 通过；
- `npm run build` 通过；
- 原项目列表和七阶段路由逐项冒烟；
- 登录后可进入两个平级工作区；
- 对话、上传、Skill、Prompt 和草稿确认可用；
- 图片和视频独立入口可用；
- 视频节点可以保存、连接、确认、查询和展示结果；
- 管理员可按用户看到 Token 和金额；
- Vercel 部署成功并完成线上登录验证。

真实模型 smoke test 使用最小成本参数和安全提示词，不在输出中记录 Key。

## 14. 分阶段交付与 Git 策略

每个阶段完成测试后独立 commit 和 push 到 `origin/main`：

1. 本设计规格；
2. 私人空间数据库、RLS、Storage 和消耗流水；
3. 私人空间、文件夹和对话 API；
4. AI 创作台外壳、同级入口和对话 UI；
5. 独立生图页与图片画布；
6. Seedance 视频画布；
7. Skills、Prompt 和发送到导演项目；
8. 管理后台用量、金额、额度与 CSV；
9. 全量回归、线上验证和文档更新。

数据库迁移必须先以向后兼容方式上线。任何阶段若验证失败，不推送半成品；已上线旧功能仍可继续运行。

## 15. 已确认的最终决策

- 采用双工作台门户，AI 创作台与导演台平级。
- AI 创作台不依赖导演项目。
- 视觉采用已批准的第二版：GPT/Claude 式对话层级、TapNow 式视频画布、FG Studio 原有设计令牌。
- 旧导演台界面不改，只增加入口和新路由。
- 对话、生图、生视频都有独立入口。
- 视频默认使用画布。
- 媒体生成必须二次确认。
- 全部指定文本、图片、Seedance 普通版和 Filter-off 模型均可由用户选择。
- 两个 Gemini 3.1 图片模型以实验状态接入。
- DeepSeek 两个文本模型继续保留。
- 继续使用现有服务端 Wetoken Key，不在代码或文档中重复其值。
- 增加按用户统计 Token、媒体用量和金额的管理后台。
- 每个独立阶段验证后提交并 push。

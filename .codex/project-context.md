# FG Studio 项目上下文

## 项目定位

FG Studio 是一个面向个人创作与小团队协作的 AIGC 视觉工作台，目标能力接近 LibTV：对话创作、剧本、分镜、角色与参考素材、图片/视频生成、媒体资产管理和无限画布。

## 媒体存储决策

- 当前 Synology NAS 地址：`192.168.0.14`。
- DSM 管理页面当前使用 `http://192.168.0.14:5000`；该端口只用于局域网管理，不应直接暴露给前端或公网。
- NAS 当前桌面可见 `File Station`、`Synology Drive`、`WebDAV Server`，尚未确认是否安装 `Container Manager`。
- 如果 NAS 没有 `Container Manager`，不需要更换 NAS，也不需要立即部署 MinIO。
- 当前优先方案：`Web 后端 → SMB/NFS 挂载目录 → NAS 共享文件夹`。
- 建议为媒体建立独立共享文件夹和专用账号，账号只拥有该目录的读写权限。
- 文件可以按以下类型分目录保存：原始素材、预览/缩略图、HLS、剧本导出和临时文件。
- 数据库保存项目、剧本、分镜、媒体元数据、版本和权限；NAS 只保存媒体文件。

## 上传与访问

- 浏览器上传应先进入项目自己的后端 API，后端负责鉴权、文件名/类型/大小校验、落盘和媒体元数据记录。
- 没有 MinIO 时，推荐由后端写入 SMB/NFS 挂载目录；浏览器不能直接把 SMB 目录当作 OSS 使用。
- `WebDAV Server` 可以作为 HTTP 文件访问的内部/小规模备选，但它不是标准 OSS/S3 API。
- 如果未来明确需要浏览器直传、分片上传、预签名 URL 或标准 S3 API，再考虑在支持 Docker 的机器上部署 MinIO 或迁移到云 OSS。
- 不要把 MinIO 的数据目录随意放在 NAS 的 NFS/网络文件系统上；如果部署 MinIO，应遵循其存储一致性要求。

## 当前会话结论

- LibTV 公开集成资料显示支持上传图片和视频到 OSS 并返回 OSS URL，公开资料标注单文件 200MB 以下。
- “浏览器选择文件上传”不等于“浏览器直传 OSS”。本项目可以先实现 `浏览器 → 后端 → NAS`，后续再升级为 `浏览器 → MinIO/OSS`。
- AIGC 视频平台还需要后续处理链：FFmpeg 生成缩略图、预览、HLS、字幕或音频波形；NAS 负责存储，不会自动完成转码。

## 验证前提

- 实施前需要确认 NAS 型号、DSM 版本、SMB/NFS 是否可用，以及 Web 后端运行在本机、局域网服务器还是 NAS 上。
- 任何公网媒体分发都需要额外考虑 HTTPS、鉴权、访问带宽、CDN 和内容授权。

## 建议的入口和操作流程

在第六板块左侧工作台增加独立的「广告工作台」，与「短剧 Agent」「自由画布」平级。使用 AdCraft 原生前端和生产后端作为独立服务，不用 FG 页面仿制其流程。

用户操作：

1. 创建广告项目：选择所属小组、负责人，输入产品、卖点、目标受众、投放渠道、时长、比例、风格及预算；可以从公司素材库引用角色、产品、声线和参考广告。
2. 广告 Agent 逐步澄清需求，给出创意与脚本方向；用户确认后才进入相应制作步骤。
3. 原生广告画布展示各步骤、依赖、候选及进度，可以只改一镜或一个资产，并保留已确认结果。
4. 图片与视频生成前通过 FG 模型目录选择参数并显示人民币报价；批量任务显示总报价和预算余额，不能因上游自动流程而绕过确认或预算。
5. 成片、原素材、候选和工程持久化；用户回到广告项目时恢复原工程。管理员按人、项目、小组查看统一人民币账单。

广告项目可以关联一个故事，但不强制所有广告来自故事。一个项目允许多个广告方案或画布，例如不同比例、地区、受众、时长、版本。关系用稳定 ID 存储，不按标题拼接。

## 已核验的运行结构

| 单元 | 上游入口 | 用法 |
| --- | --- | --- |
| Web | `apps/web`，React 19、Vite、React Flow | 保留原生首页、工作流画布、时间线及候选管理；适配嵌入式路由和 FG 品牌 |

上游 `compose.yaml` 默认只绑定 loopback 的 Web 端口。`deploy/nginx.conf` 将 API 来源标记为本机；这是其本地凭证设置边界，不能原样公开到团队局域网。

## 必须完成的四个 FG 接口桥接

### 1. 身份和权限

审阅到的业务 API 以运行时工作区与项目 ID 为中心，未提供可直接复用的 FG 用户、小组和项目 ACL。外层登录页或 iframe 本身不能替代对象权限校验。

- 所有外部入口由 FG 登录态网关验证，后端获得可信用户身份；客户端不能自行提交有效的用户编号。
- 为广告项目建立 FG 用户、小组及成员关系，并在读取、修改、生成、导出、素材访问时检查项目权限。
- 团队成员共享允许协作的项目，保留创作者和操作记录；不能将所有自由项目自动合并为全员可编辑。
- 原版 API Space 的公司密钥设置改为超级管理员管理；普通用户只选模型，不能读取或修改公司 API Key。

### 2. WeToken 模型与生成任务

上游有 OpenAI Compatible 文本配置，以及 Ark、OpenRouter、MiniMax 等媒体适配器；不是填一个 WeToken URL 就能让所有生成种类自动兼容。

- 新增 FG 媒体 provider，调用现有 FG 服务端生成队列；保留 AdCraft 的 workflow/node/task ID，附带 FG project/canvas/user ID。
- 接受任务后记录 FG task ID，恢复时查询该 ID；禁止断线后重新提交并再次计费。
- 文本 Agent 的模型调用也经过 FG 服务端模型中转，保留工具调用与流式响应；不能漏记后台 Agent 的文本费。
- 只显示 FG 已开启的模型和参数能力。Gemini 3.5 Pro 当前权限不足，不因 AdCraft 中有类似入口而启用。
- 提取 `x-oneapi-request-id`，与 WeToken Reference ID 对账；本地任务 ID、上游任务 ID、费用引用 ID 分别记录。
- 暂无音频生成供应商适配的阶段，允许使用上传的音频，标明未配置的音频生成步骤；不把 mock 输出当作真实成片。

### 3. 保存与素材复用

`v2_storage_adapter.py` 已实现内容哈希、校验、临时文件与原子发布，可以复用。其 SQLite 路径在 `persistence/database.py` 中固定为数据目录下 `v2/adcraft.sqlite3`。

- 媒体目录接到 NAS 的独立广告目录，原图、参考视频、音频、候选、成片及工程附件都由服务端保存。
- 复用 FG 公司素材库，引用资源 ID、版本和来源；生成媒体可进入统一资产库。
- 不能简单把当前整套数据目录放到网络共享盘就认为数据库可靠。先分离数据库路径与媒体路径：事务数据库放 Mac mini 本地持久卷，使用 SQLite 一致性备份到 NAS；数据库也是服务器保存，与浏览器缓存无关。
- 恢复依据服务器工程、事件和任务，浏览器仅可作缓存；保存失败明确提示，不能显示「云端已保存」。
- 保留原生候选及版本恢复机制，媒体清理前检查引用，不对项目仍使用的文件进行物理删除。

### 4. 人民币成本与资源调度

- 复用 FG 报价和费用核销，不单独维护第二套汇率或模型价格；前台只有人民币价格，管理后台保持预估、服务商回报、已核销的区分。
- 待账单核销不是零费用。费用按调用时的用户、小组、项目快照归属，成员调组不重写历史账单。
- 广告原生编排的每一步必须进入同一队列、频控和预算。团队模型任务上限与 CPU 合成并发分开；100 个云端任务不等于 Mac mini 同时渲染 100 个成片。

## 落地顺序与验收

1. 独立容器和数据目录、FG 登录与项目 ACL、品牌和导航，先验证未登录不能读取数据、两个用户项目不串用。
2. 原生广告项目与画布恢复、素材上传 NAS、公司素材引用、免费 mock adapter 离线验证流程。Mock 模式仅用于开发，不向用户宣称真实生成。
3. WeToken 文本和媒体桥接、参数报价、Reference ID 对账、预算确认和任务恢复。暂不发起付费验收，沿用用户「不要再生成收费图片视频」的约束。
4. 复用原生时间线合成，用本地验收视频与音频测试导出，验证人物或产品素材、候选、工程、视频文件均可在重新登录后恢复。

以上桥接已在 FG 1.2.3 实现，运行入口和首批支持范围见 [广告工作台说明](README.md)。权限、队列适配、工程及 NAS 恢复使用免费验收；不自动重跑付费成片，前五板块保持原服务。

# 第六板块 v2：画布优先，新 Agent 独立重建

2026-09-22。本文根据用户本轮纠正更新，优先于上一版“六类 Agent 卡片”的信息架构。

## 已确认的产品方向

1. 制作画布是主要工作空间；保留现有超级画布的有效工具与能力，重新组织入口和视觉。
2. 旧 Agent 很不好用。**不沿用旧 Agent 的对话流程、决策、前端循环编排、状态库或节点执行桥接实现。** 旧源码只用于理解现有能力与迁移接口。
3. 编剧与导演合并成剧本工作台的「编导助手」，提供批量真实剧本生成；导演方法作为 Skill，镜头执行时也能调用。
4. 画布内「制作助手」是主要 Agent 入口，支持对话、选择 Skill、读取选中素材、创建/修改节点、生成图片/视频/音频，并返回真实任务结果。
5. 美术负责前期人物、场景、道具、风格与关键帧资产，可作为画布制作助手的工作模式。资产必须能在后续镜头里真实引用。
6. 推进管理与制作共用项目、分集、任务、版本和费用，不能只在导航里放两个互不关联的页面。
7. 全部开发仍只在 `D:\FG.AI\fg-studio-production-lab` 的新模块路径；旧五个模块与运行服务不修改。

## 1. 新界面应怎样工作

进入项目即进入制作画布。顶部只保留制作画布、剧本工作台、美术资产、项目推进和 Skills 库。不要再做大面积欢迎页、Prompt 海报墙或重复 Agent 入口。

- 左侧：剧集/分集，角色、场景、道具、镜头和输出资产。支持检索、收藏与引用来源，资产库与节点列表可切换。
- 中央：无限画布，节点可以人工操作，也可以由 Agent 操作。同一套工具契约服务两种入口，不能出现 Agent 能做但界面无法编辑的黑箱节点。
- 右侧：制作对话。用户选节点后，明确显示引用对象、版本、已选 Skill、目标模型和输出要求；需要修改参数时再展开检查器，避免同时展示几十个开关。
- 底部：新增节点工具和缩放；运行时展开任务托盘，显示真正的排队、运行、等待确认、失败、完成状态。
- 节点上：最常用的继续生成、编辑、引用、预览；蒙版、裁剪、切图等二级工具收进对象菜单，保留可配置快捷操作。

视觉采用低饱和石墨灰、细分隔线、较克制的鼠尾草色状态标记，主要视觉重心由作品承担。控制页头高度，留出画布；不要用炫光、巨大卡片或泛化管理台指标来表达“高级”。画布和业务详情有各自密度，长文本留给剧本阅读器。

窄屏保留画布与抽屉式制作助手；批量制作主要面向桌面。后续需要实测大屏/笔记本缩放、快捷键、中文输入、触控板和长时间使用，不能只看一张大屏截图。

## 2. 三个工作入口，避免职责重叠

| 入口 | 用户要做什么 | Agent 的职责 | 主要输出 |
|---|---|---|---|
| 剧本工作台 / 编导助手 | 多方向提案、整季框架、批量分集、改稿 | 使用编剧与导演方法开发故事；维护人物状态、因果与连续性 | 方向候选、圣经、分集大纲、剧本版本、初步镜头需求 |
| 画布 / 美术模式 | 人设、服装、场景、道具、参考图、关键帧 | 从已确认故事抽取资产需求，生成并比较候选，形成锁定资产 | 带身份/场景/风格标签的资产版本与引用 |
| 画布 / 制作助手 | “用这些素材生成镜头/视频”“只改这段” | 阅读当前画布和真实引用、调用适配 Skill、执行工具、检查结果与局部修复 | 可编辑的镜头和生成节点，真实图/视频/音频结果及费用 |

质检作为各阶段的可调用能力及审核队列，不必额外建一个独立聊天页面。策划也先放在选题与提案阶段，不再扩展一排角色卡片。

编导负责故事怎么成立；制作助手负责把已确认内容落实为资产、镜头和成片。镜头语言在两者之间传递，但不要让两个 Agent 各自重写剧本、互相覆盖版本。

## 4. 新 Agent 的完整执行流程

用户示例：“用艾琳和书房这两个资产，生成三个不同运镜的开场视频，保留同一服装；每段 8 秒。”

1. 服务端建立会话并绑定 projectId、episodeId、canvasId；用户身份从会话获取。
2. 读取选中节点及其真实资产 ID、版本和生成权限。缺少图像时先准备资产，不能只靠文字声称“已经参考”。
3. 用户可手动选择 Skill，也可让 Agent 推荐。展示所选方法和输出目标；选择只影响本次或明确设置的默认范围。
4. Agent 产出工具调用，而非只输出聊天建议。操作包括读取素材、写镜头节点、连接引用、配置模型、提交生成、查询结果、回写产物。
5. 可逆的画布编辑按用户授权执行并可撤销；方向变化、新预算上限、长批次或新增外部素材传输按具体边界设确认点，不把每个工具调用都变成弹窗。
6. 服务端验证工具输入、图版本、资产归属和预算，事务写入变更与任务。重复的 turnId+callId 不重复执行。
7. Worker 执行真实供应商请求，保存 requestId，持续记录事件；前端只订阅展示，不承担运行生命期。
8. 返回的媒体保存为资产版本，再回写节点。只有真实结果和可访问文件验证通过，节点才显示完成。
9. 失败时指出具体原因、受影响节点及可修复操作。用户说“第二个镜头动作太快”，只重做第二个变体，其余成果与审核版本保留。

### 新工具契约（设计，不表示已实现）

只读：`canvas.read`、`nodes.query`、`assets.inspect`、`skills.describe`、`models.capabilities`、`jobs.get`。

写入：`canvas.patch`（创建/更新/连线/分组/布局，携带 baseRevision）、`assets.bind`、`generation.submit`（返回 jobId）、`jobs.cancel`、`media.compose`。

每次操作携带作用域、输入版本、幂等键和审计事件。模型只提供业务参数，不能提供可信用户身份、任意文件路径或数据库指令。可选工具根据 Skill 与当前任务收窄，不把本机 shell 权限作为“万能创作工具”发给用户上传的 Skill。

Skill 正文、工具定义、项目上下文、最近对话分别管理。只加载本次需要的一个主 Skill 与少量辅助 Skill；附属文档按允许路径读取，不截断丢掉关键约束。新运行器不能只执行固定问卷，也不能根据几个关键词套模板冒充 Agent。

### 参考案例的具体证据

- [Infinite Canvas](https://github.com/tigerowo/infinite-canvas)：`web/src/app/(user)/canvas/agent/canvas-agent-tools.ts` 明确列出读画布、读选中节点、读 Skill 附属文件、创建/修改节点、分组/排布、图像编辑与视频/音频生成。采用其“明确工具契约”的思路，非复制实现。
- [TapCanvas](https://github.com/anymouschina/TapCanvas)：`apps/hono-api/src/modules/ai/tool-schemas.ts` 的 capability manifest、`tapcanvas_flow_patch`、引用资产及确认基准约束；project/chapter 的 canvas-patches 路由。值得借鉴图补丁、引用绑定和版本约束。源码描述部分节点仍由 web app 执行，新系统需要补足后台任务运行，不能照搬后又依赖开着浏览器。
- [AID Studio](https://github.com/gzxx-2025/aid-studio)：上一轮检查的 Skill invoke/respond、上下文版本、批次部分失败、取消和事件回放。用于人工确认与耐久执行层。
- [Open AI Canvas](https://github.com/ddcat-ai/open-ai-canvas)：任务租约与执行事实；[Huobao Canvas](https://github.com/chatfire-AI/huobao-canvas)：类型化节点依赖和服务端队列。功能存在不代表所有方案已满足你们的剧集连续性需求。

## 5. 产品中的制作 Skill 范围

产品菜单只放 `lib/production-lab/production-skills.json` 中 18 个漫剧相关 Skill：4 个编导、4 个美术和 10 个制作。其他个人工作、平台、投放、开发和通用海报 Skill 不进入第六板块 Skill 库，也不进入浏览器包。

当前 9 个 Skill 的正文及必要参考文档已服务端打包：4 个编导 Skill 与 5 个视觉/制作 Skill。每轮最多选两个；未部署的制作相关 Skill 显示为未适配并禁用，不能伪装成能运行。用户选择的 Skill 版本记录在请求或节点上下文中。

正式 Skills 管理需要保存适用任务、所需输入、输出 schema、模型/工具能力、版本及测试样例，并提供发布/回退。外部服务流程、依赖本地执行器的 Skill 和纯方法 Skill 必须分开适配，不能只因为在用户本机存在就当作产品运行器。

## 6. 批量剧本工作台

一个批次明确：项目/系列、已选方向、锁定故事圣经、分集大纲、集号范围、单集目标时长、对白/说明语言、主 Skill、辅助 Skill、候选数量、预算上限。

先大纲再正文，跨集依赖用人物状态与前集摘要传递。可独立的提案可并行；同一条强连续性故事不能无上下文地同时生成几十集。每集必须有实际正文、输入版本和状态，不以“新建一张卡片”冒充剧本完成。

结果界面以表格+剧本阅读器展示：批次状态、集号/标题、字数/预计时长、连续性问题、待审版本、费用。支持重写单集、局部改稿、比较版本、批量送审、导出及“发送到画布”。送到画布的是具体已审版本，后续修订显示过期提醒，而不是偷偷替换制作依据。

## 7. 这次已经落地与仍未落地的边界

已经实现独立第六板块：画布优先界面、文本/角色/场景/镜头/视频/音频节点、连线、拖动、平移缩放与惯性平移、撤销/重做、自动排布、明暗模式、选题与项目推进、模型比较式批量剧本、多项目分集任务、素材本机上传分类。

画布按用户/项目/分集存独立本机副本，并写入新表 `production_lab_canvas_graphs`；服务端图有版本比较并交换。冲突时可下载本机图，或先保存本机恢复副本再载入服务器图。批量剧本候选保存到实际分集任务，选中版本会以带模型/来源信息的节点写回同一分集画布。

新制作 Agent 已替换固定问卷与旧 Agent 流程：服务端读项目、分集、画布节点索引、选中节点与上游文字依据，载入用户选择的制作 Skill；模型可动态追问并返回新增节点或修改选中节点的操作草案，用户确认后才写画布。它现在仍是**文字模型 Agent**：它看不到本机图片二进制，不能运行图像/视频生成器，也没有后台媒体任务队列；视频节点只是已标记的制作草案。

官方素材图库目前只是浏览器内待发布草稿，团队共享、管理端审核与版本发布尚未接通。管理视图已能看新板块模型配置和文本剧本运行记录；账号管理、供应商账单/人民币对账、媒体队列与全量内容审核未接入。当前的惯性平移不等于液体物理引擎。GPU 超分和去水印按要求延期。

旧画布功能对应表仍是验收清单，不代表全部迁完。旧 `/creator`、其模型与 Agent 状态、全局存储和部署都没有被第六板块复用或更改；真实媒体服务未来必须用第六板块自己的授权、存储、预算、任务和资产回写适配层。

## 8. 下一步开发验收顺序

1. **视觉与画布交互回归**：真实多人项目和分集切换、节点多选/分组、快捷键、连线输入、引用预览与撤销范围；对照旧画布清单逐项记录通过/未通过。

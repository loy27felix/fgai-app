# 第六板块独立发布

FG 版本 1.2.0。第六板块的原生后端、前端与网关独立构建、独立发布；原五个板块的主应用继续运行原镜像，不执行其启动迁移。

## 工作区入口

为了向全部成员显示第六卡片，同时避免重启原应用，工作区使用公司源码构建的平行 Next 容器。仅 `/workspace` 请求转给该容器。原五个板块入口仍使用普通链接导航到原服务。

平行入口加入既有平台 Docker 网络，不增加主机公开端口；沿用原登录验证和数据库连接。原媒体挂载仅以只读方式继承，不在此容器执行数据库迁移、定时任务或生成任务。

`/_next/static/` 优先从原应用读取；只有不存在的构建文件返回 404 时，才转给平行入口。避免替换正在使用的旧页面资源。Nginx 原配置及运行时配置必须各自备份，语法检查通过后热加载。

需要回退时恢复两份 Nginx 配置、检查后热加载，并停止平行入口；第六板块可独立回退到上一组后端、前端与网关镜像。不要删除数据库、NAS 文件或 Docker 持久卷。

## 发布顺序

1. 构建阶段运行网关、模型参数、NAS 上传、共享权限和保存冲突测试。包含全部 Markdown 技能包，使用 UTF-8 与 NUL 分隔清单，避免中文目录名漏包。
2. 检查第六任务队列为空。生成 PostgreSQL 备份到 NAS，以 `pg_restore --list` 校验，并保存旧环境、镜像与路由配置。
3. 先启动网关，应用 FG 附加表；再启动原生后端、前端。等待健康检查，失败时回退服务镜像，保留用户数据。
4. 导入历史小组时兼容原系统非 UUID 的小组标识。只首次导入成员分组；后续刷新仅同步平台账号，不覆盖管理员调组。
5. 仅共享故事项目已经使用的资源和资产。个人画布与上传不全局公开。保存冲突应返回 409，媒体授权与画布保存处于同一事务中。
6. 检查工作区卡片、故事详情、小组、多个分集画布、人民币报价与费用页。无需为界面检查发起收费模型请求。
7. 记录公司 Git 提交 SHA 和 FG 版本。核验原主应用镜像 ID、启动时间、存储和队列保持原状，再正常推送源码，不强推。

## 数据边界

实际选题内容和人员映射、NAS 素材、供应商会话、API Key、费用 CSV、数据库备份和环境文件留在私有存储，不提交到公开仓库。Gateway 协议包、产品代码、制作技能与部署合同可进入公司源码仓库。

公司主分支自动部署通常会重建原应用。当前独立路由配置造成原工作区有未提交配置，自动部署会安全拒绝更新；不要自动清理该配置或执行原平台的强制部署。后续全平台升级必须同时迁移这些独立路由，并另行验证原五个板块。

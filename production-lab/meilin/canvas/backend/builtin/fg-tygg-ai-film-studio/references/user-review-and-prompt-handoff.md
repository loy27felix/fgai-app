# 用户确认与交付分流（规则 3.2.4）

本页是人工确认后的唯一分流依据，适用于其他文件引用的 prompt_export 阶段。制作前的访谈、分镜展示和静态/动画分别确认，按 [阶段展示与确认](production-approval-gates.md) 执行；不要用本页“直接交付”跳过前面的查看点。

| 当前情况 | 下一步 |
|---|---|
| 用户只确认静态模型 | 进入约定的镜头、主体与关键道具动画制作，不扩大为动画已认可 |
| 用户认可当前模型与动画 | 采用该 revision，编写完整视频提示词，并完成已约定但尚缺的参考视频导出 |
| 用户指出模型/动画修改 | 回 Blender 定点修改受影响范围，再让用户查看；保留其他已采用决定 |
| 用户只要提示词、已有可用预演或明确取消视频导出 | 直接按实际材料交付文本，不为流程强制新增视频任务 |
| 用户反馈生成结果的外观、身份或细节偏差 | 先调整对应图片/标签/提示词；只有结构本身需改变才回 Blender |

“没问题、认可、按这个来”等针对已展示的当前模型和动画的认可足以进入交付。回复必须能对应具体产物与范围；确认了静态场景不等于动画也被认可，确认资产图也不等于模型被认可。不重复询问已经清楚的同范围批准。不要再运行碰撞、Standard/Release、全片审片、性能基准或为了 AI 再看一遍而补渲染。已有技术证据保持真实状态；人工认可不等于脚本通过，脚本未执行也不能推翻用户判断。

**必要导出是完成已约定产物。** 人工认可后禁止追加的是复核流程；用户目标包括参考视频时，不能因“直接提示词交付”漏掉视频。按 [视频交付](reference-video-delivery.md) 复用同版本视频或小批次完成干净输出，仅核对实际产物的保存与媒体信息，不重新评价动画。

从已有记录确定批准版本，不扫描全场寻找新问题。已知手动调整影响当前资料时，仅对齐相关镜头、时间或事件；用户对该调整的认可继续有效。若用户所认可的是哪个文件确实无法判断，只补必要定位信息。

**新材料的写作核对仍须完成。** “认可后不复核”指不重新审查已采用动画；编写或修改提示词时，仍按 [写作核对](ai-video-and-asset-prompts.md#写作核对与按反馈修订) 对齐已知素材版本、主体、动作归属、方向、时间和起止状态。先解决相关来源冲突再交付，不用用户的动画认可为相反文字背书；这不触发全片播放、补渲染或重复确认。

数据检查、画面观察、用户认可及实际生成各自说明证据范围。局部采样不证明完整动作或观看效果，文件校验不证明人体手别或物理过程。未明确的状态保留未知，只在阻碍当前任务时补定位；用户反馈可作为用户报告记录，不冒称助手已经查看成品。

人物图按 [人物图准备](character-image-assets.md) 与场景/道具同批推进。缺图时可交完整条件稿并保留已给人物生图提示词；只缺人物外观不回 Blender。工程、视频、文本、外观图片、上传绑定及生成结果分别记录，已约定材料尚缺时不称整项任务完成或可直接投喂。

视频提示词按 [提示词规范](ai-video-and-asset-prompts.md) 与 [模板](reference-prompt-template.md) 从逐项素材职责开始，写人物/道具对应、已确认摄影与声音、分大体时段的动作表演及连续性。剧情的关键交互、结果和必要表演进入正文；文戏的关键转折写出具体可读的表情/声音变化及触发，不能只给剧情梗概或情绪名称。段内自然衔接，不逐项转抄微动作时间表。未上传可交带文件对照的计划@编号稿，已有实际上传标签才记绑定完成。文件存在、占位图和普通文字都不证明已上传。

实际反馈认可某稿的结构或自然度后，保存该基准与有效维度；后续身份、入画、服装等歧义先按 [生成偏差归因](ai-video-and-asset-prompts.md#生成偏差归因) 局部修订，不默认改写顶部、删除基本时段或收紧全部身体表演。没有结构问题不回 Blender，不自动生成、付费测试或反复抽卡。此条不把用户的效果反馈冒充助手亲见或统计验证。

完成声明区分“参考视频与提示词已交付”和“最终AI影片已生成/剪辑”。若合同包含生成与剪辑，未完成时保留待办，不把Blender交付冒充全片完成；若合同止于提示词交付，说明用户接下来如何生成即可。

交付当前章节时，同时根据已采用资料更新 [项目入口、章节进度与连续性](project-documentation.md)，留下下次恢复所需的故事、角色、偏好和结束状态。这个文档交接不增加AI复核，也不授权制作全剧其余部分；`本段参考交付完成`不等于`整剧完成`。

# Hyper3D 静态场景资产（规则 3.2.7）

本分支只改变选定对象的模型来源。沿用原 Blender 的空间拓扑/净空 → 环境与道具 → 静态确认 → 动画 → 交付流程；人物代理、交互、运镜、资产图及提示词规则不变。已有项目不因升级自动重走流程。

## 接入顺序

**本批必要结构资产图已认可 → 选择建模方式 → 选择 MCP 后检查安装与连接 → 连接通过后预估对象并给出范围选项 → 确定逐模型质量 → 生成、下载、登记 → 回到原 Blender 建模流程。** 人物图仍可按原规则同步准备，不新增前置条件。

每次只处理当前未决步骤。用户已给的路线、名单、质量和委托直接复用；未答不能当作接受推荐。对象预估与范围选择同轮交付，不另设“预估报告确认”。交互沿用 [互动共创](interactive-development.md) 的正文或受限时文档方式；本分支的路线、范围和质量各有两个真实选项，不强凑第三项，不新增系统问卷。

### 1. 资产图确认后直接选择建模方式

此时只说明两条路线，不提前筛选 MCP 对象或估算数量。下面是提问模板，题号接续项目记录：

```text
Q 本轮场景采用哪种建模方式？
A. 直接用 Blender 制作：按已确认的资产图建立场景与简化模型。
B. Blender 结合 Hyper3D MCP：生成选定的异形陈设家具、复杂雕塑或特殊装饰，下载无材质模型后由 Blender 整合。
```

选择直接 Blender 就跳过本页其余分支。明确选择 MCP 后先检查连接，不能在等待安装或授权期间提前制作候选方案。用户专门要求测试模型或诊断连接时，按其明确范围执行，不为独立测试补整套影片流程。

### 2. 检查安装、授权与连接

- 发现或加载当前客户端的 Hyper3D 工具，查看可取得的服务配置、连接和授权状态。工具尚未加载不能直接等同于未安装；有效的既有连接直接复用。
- 没有安装或配置时，引导用户打开 [Hyper3D](https://hyper3d.ai/)，登录账号，点击右上角 **MCP** 按钮，按页面中对应当前客户端的说明完成接入和 OAuth 授权。入口布局如有变化，以实际页面为准。引导示例：“请登录 Hyper3D，点击右上角 MCP 按钮，按页面说明接入当前客户端并授权。完成后我会检查连接，再评估适合生成的对象并给你范围选项。”
- 已有配置但失效时，只处理未授权、禁用或未加载等实际缺口，复用 `hyper3d` 服务，保留其他配置。用户明确让助手配置时才执行相应写入；传输和地址按当前官方页面核对，既有 Streamable HTTP 接入地址为 `https://api.hyper3d.com/api/mcp`。本分支不要求改用其他客户端或平台。
- 登录网站或安装命令成功不等于 MCP 已可用。用客户端连接状态、成功的 MCP 握手与工具发现等只读证据确认；有真实既有任务时可按需要查询，不能编造任务 ID 或提交付费生成作连接测试。
- 需要重启或重载客户端时明确说明，保留当前选择，恢复后重新发现工具并核实连接。用户说“已安装/已授权”后仍核实实际状态；不可用则停留在连接准备。已有方案在恢复时断连，保留原名单，连接恢复后继续未完成部分。

### 3. 连接通过后预估对象，同时给出范围选项

依据已认可的资产图、剧本、分镜和现有资产，按下节边界筛选并说明每个推荐对象的具体收益。生成数量是**新源模型款数**，不是场景摆放数量；例如一款壁饰摆放八件，只需一个源模型。

- **少量重点，推荐**：通常 2–3 款，优先解决重要且难以经济构形的静态异形对象。
- **中等数量**：通常 4–6 款，包含重点组全部对象，再加同样符合收益与负载条件的次要陈设。

两组都列全具体名称、款数和一句理由，允许按名称增减。数量不是配额：只有一款值得生成就只列一款；没有第二组合理候选时不虚构套餐。没有合适对象时说明原因并建议直接 Blender，等待用户决定，不为使用 MCP 新增布景。

示例仅适用于资产图中已存在且无角色交互的复杂陈设：少量为“贝壳形展示椅、浮雕封闭边柜、抽象雕塑”；中等可再加入“兽首壁饰、不规则装饰灯座、卷叶雕花画框”。普通曲面或规则装饰能直接建模就移出名单；不得照抄示例或加入常规植被凑数。

## 对象筛选边界

**普通物体优先 Blender，MCP 聚焦具有必要复杂形体的静态资产。** 同一对象按全部相关镜头判断，不能只根据名称或“背景物体”标签决定。

| 处理方式 | 对象与边界 |
|---|---|
| 优先 Blender 或已有轻量资产 | 常规树木、灌木、草花、仙人掌、普通岩石、简单花瓶、桶箱、常规桌椅柜、规则灯具与栏杆；使用简化网格、曲线、旋转体、共享模块或原有程序化方法 |
| 可推荐 MCP | 仅作陈设的异形家具、雕塑式封闭边柜、抽象圆雕、兽首壁饰、复杂立体雕饰和特殊装饰灯座；固定形态、参考明确，必要轮廓在镜头中可见 |
| 可按部件采用 | 已有独立参考、边界清楚的柜面浮雕或家具雕饰；简单主体仍用 Blender，不自动拆整场或依靠模型拆分补出缺失结构 |
| 默认排除 | 需要坐靠、握持、操作、开合、破坏、变形、内部结构或精确接触的家具和道具；车辆、人物/表演动物/角色手部，以及决定通行的楼梯、门、地面和通道 |

先复用项目及已登记库中的合适资产，再比较合理的 Blender 做法。制作脚本费时、构建时重计算、播放时负载是不同问题：静态构形可考虑一次固化，不能因原先写法低效就推荐 AI。只靠材质、颜色或微小纹理体现的特点，不算白模几何收益。

同时评估 AI 结果的清理代价。密集镂空、极细构件、复杂内层和必须精确拼接的对象，不能因“难做”就优先生成；缺件、粘连或修复预计过重时换可控方案。没有同等画面需求下的可比较证据，不声称 AI 比 Blender 更省算力；只预计省制作时间时如实说明，不为比较先造两套场景。

普通植被不进入默认两组候选；用户另行指定特殊对象时再评估。后续剧情使某对象变成强交互对象时重新判断资格，不擅自改剧情、加骨骼或启动 BANG 拆分来适配。

## 4. 名单确定后选择质量

数量与精度分别选择：**标准，默认推荐**与**精细**；只展示选中对象的名称、逐款目标面数及源网格合计，允许仅提高其中几款。生成模型的最低基准为 **10,000 三角面**，对象复杂时标准档也应更高，不统一压到下限。

| 形体预算示例 | 标准目标三角面 | 精细目标三角面 |
|---|---:|---:|
| 较小但有必要立体轮廓的独立饰件 | 10,000 | 20,000 |
| 有明显形体层次的雕塑、壁饰或灯座 | 20,000 | 40,000 |
| 复杂异形陈设家具 | 30,000 | 50,000 |

表中是选档起点，不是各类别已实测合格的保证。既往六款基础物体/植物测试支持已接受的最低质量标准，不意味着新家具已测试，也不构成默认生成清单。按实际参考、景别和实例负载调整；常规上限参考 50,000 三角面，更高目标需明确对象和负载，不自动整批升档。

固定参数为 `tier: Gen-2.5-Extreme-Low`、`mesh_mode: Raw`、`geometry_file_format: stl`，逐模型显式指定 `quality_override`。精细档主要提高几何目标，不静默改为 Medium；形体误解或粘连先检查输入与描述，面数增加不能保证解决。确需改变生成档位时针对具体对象说明并取得相应选择。

**材质不是选项。** 所有本分支资产只下载无材质 STL 几何，不下载贴图或保留生成的外观材质，Blender 使用统一白模显示。当前 MCP 未提供关闭服务端材质生成的参数，不能套用其他 API 的 `material=None`，也不能承诺跳过服务端纹理计算。最终资产图风格与视频美术职责不变。

最后的质量问题前给出可执行的本批摘要：具体名单、参考来源、两档逐款参数与合计、全部无材质、生成后下载到本项目模型目录并用于 Blender。用户选定后直接执行已明确范围，不再重复问“是否开始”。只选择 MCP 路线尚未确定名单和质量时，不提交付费任务。

## 生成与恢复

- 正式项目使用实际采用的参考图。关键道具三视图规则不变；同一对象的多视角必须同物同态，保留实际输入顺序与来源。必要时按现有图像工作流准备清楚的单体或视角输入，不把三视图排版生成为三件物体。结构不清只补受影响对象，不重做整批图；用户指定的纯文本测试记录无图输入，不伪称有已认可图像依据。
- 提示词描述对象形体、比例、组成和必要轮廓，不混入影片镜头、剧情或角色表演。实际发现 MCP 参数后再提交；目前支持 1–5 张参考图。本地文件按实际工具的上传流程处理（`rodin_create_uploads` 后成功 PUT，再传上传 ID）；`rodin_import_images` 的 ChatGPT Chat 附件方式不能冒充本地路径上传。
- 每次生成立即保存任务 ID 和实际参数，查询原任务直至完成；等待返回超时不等于生成失败。生成提交超时不得自动重发，已有 ID 则先查原任务；没有可追踪 ID 时请用户核查 Hyper3D Mine。重新生成需要覆盖新增任务的授权，不无限抽卡。
- 完成后取得结果，按本批明确的下载范围仅保存模型文件。面向用户使用完成后的永久结果页或本地文件，不展示临时签名下载地址。下载失败先恢复下载，不重新生成模型。
- 采用标准以下载文件实测三角面为准；请求目标不当作实际值。不通过无意义细分凑下限，不擅自减面到已选基准以下。实际结果不满足本批需求时说明具体差异，修正仅限受影响资产。

## 资产登记与 Blender 对应替换

沿用 [项目记录](project-documentation.md) 和 [资产库](asset-library.md)。文件保存于绑定项目的既有模型目录；无目录时可用 `模型资产/Hyper3D/`，按稳定 `asset_id + version` 定位。当前项目源文件管理不等于共享库发布，不扫描全部硬盘、迁移旧测试或强制将完整地点拆成独立资产发布。

| 记录组 | 保存内容 |
|---|---|
| 来源与选择 | 稳定 ID、名称/用途、相关场景、替换对象、合理的 Blender 替代方案与推荐理由、参考图版本/顺序、实际提示词 |
| 生成文件 | 任务 ID、参数/状态、永久结果页、原始模型路径与校验值、实际面数 |
| 工作资产 | 采用版本、处理修订、工程内集合/网格、尺度依据、朝向/原点/包围范围、工作面数、明确的实例引用范围 |
| 进度 | 路线、连接准备、范围/质量回答、下载/导入/必要检查及静态场景展示与采用状态 |

挂接现有资产清单或等价记录，不建立互相冲突的“当前版本”，不强迫旧清单补不存在的历史字段。任务完成、文件可用、工作资产就绪、用户认可静态场景分别记录。

原始 STL 不覆盖；尺度校正、原点、必要清理在工作副本或现有 `.blend` 资产集合中完成，不强制每件创建独立工程。新生成版本与本地处理修订分开；项目引用明确版本，更新源模型前列明会受影响的实例。只改一件时建立项目内变体，其余保持共享，不回写其他项目或共享母资产。

下载登记后回到 [原 Blender 执行流程](blender-mcp-execution.md)，在对应对象处使用生成几何：

- 新场景需要该物体时直接采用，不先制作无用副本。已有对象优先替换可见网格或子集合，保留稳定对象/父级、集合、场景变换、语义锚点及引用关系；不重建整场或改动其他对象、相机、人物和动画。
- STL 坐标不当作可靠米制；依据已定尺度在源资产层校正朝向、原点与落地关系，再使用场景摆放变换。必要检查就地完成，不追加全片审查。
- 防止旧形体与新形体重叠显示，实例源不额外出现在场景原点。按稳定 ID 和导入记录恢复，避免重复追加；保留旧版本作为恢复依据。
- 同款共享、局部变体和链接依赖沿用原资产规范，使用项目相对路径，交付工程时保证必要模型依赖可解析。

仍在 [原静态确认点](production-approval-gates.md) 展示整合场景，不增加逐资产审批；确认后按原规则制作动画，已认可的同范围结果不重问。

## 实例与性能管理

沿用 [性能预算](performance-budget.md) 的硬件档位、检查频率、小批次与重操作串行约定，不新增测试门槛或默认压力测试。

- 少量重复物共享 Mesh；多部件静态物体采用集合实例；多处重复装饰可用少量源模型配合 Geometry Nodes 实例或既有点位。常规植被继续原 Blender 低面原型，不受 Hyper3D 生成下限约束。
- 分别记录唯一源网格数量/面数、摆放/求值实例数和相关镜头展开可见三角估算。例如 2 万面的壁饰有 30 件可见，壁饰展开估算为 60 万面，不能按源网格 2 万面判断负载。实例减少重复数据，不使绘制免费；无实测不宣称达到指定 FPS。
- 默认不全场 `Realize Instances`、`Make Instances Real` 或逐物体制作唯一网格。确需真实几何时只转换受影响的小副本；统计不得先实体化，嵌套实例避免重复计数。
- 使用固定种子或稳定点位，保留既定通路、构图和遮挡，不随相机移动重新随机散布。少量朝向/尺度差异可复用源模型，不为微小差异再次生成；不新增逐叶动画、风动或模拟。
- 原始与采用模型保留已选质量；必要远景代理/LOD 单独保存来源、面数和范围，低于生成基准的副本不能冒称同一标准模型。原有低面草簇和程序化物体照常使用，不要求全部对象达到 1 万面。
- 不默认叠加细分、倒角、布尔或整套修复修改器；必要清理在源工作资产处理后复用。隐藏命名、眼睛图标或相机外不代表所有求值停止，LOD 也不会仅凭命名自动生效；沿用原可见范围与稳定切换策略。
- 连接通过后的范围/质量阶段用已有记录预估；工作资产准备时核对该批实际网格，实例或修改器变化时更新相关估算。仅在实际负载变化、故障或用户要求等原规则条件下测量；现有全场扫描脚本不能宣称为局部审计。
- 超预算先用原流程处理无关求值、远景代理、非关键密度与修改器成本，保护已定空间、轮廓、人物和镜头。必须改变已确认内容、所选质量或增加付费生成时说明具体影响并取得对应决定。用户认可模型与动画后仍直接交付，不追加审片、渲染或性能复核。

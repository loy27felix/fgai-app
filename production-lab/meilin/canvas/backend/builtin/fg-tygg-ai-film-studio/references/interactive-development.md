# 互动共创：完整创作访谈（规则 3.2.1）

目标是让用户决定最终影片的内容和观看方式，再设计 Blender 结构参考。详细不等于重复：已有明确答案直接继承；没有答案的核心方向要真正问到，或得到对此范围的明确委托。不能把“只补缺口”解释为只问两三个问题就定稿。

## 沟通形式

聊天正文是默认提问入口，文档是同步记录。**每个尚未确定的创作选择，默认在聊天正文写出问题和三个简短候选A/B/C，同时明确允许自由描述、组合或委托。** 正常情况下不以文件链接代替正文提问，不以单一推荐替代三个候选。当前会话限制正文呈现且允许文档交互时，按下节直接交付完整问题文档；用户另有明确的文档交互要求时也按其范围执行。

本Skill的“不要系统选择框”仅指不调用`request_user_input`、`request_user_input_async`等工具生成问卷、选项卡、弹窗或类似控件。正文中的Q编号及A/B/C文字不是系统选择框，属于用户要求的交互形式，不得将工具禁令扩成正文选项禁令。

### 会话规则冲突的处理

用户已授权：**当前会话限制正文问题或选项呈现、但允许通过文档交互时，将问题和选项写在文档里，让用户查看文档后回答。** 项目目录已明确时直接执行，不再询问是否同意改用文档；不为凑正文版式省略候选或改用系统选择框。

执行前先满足 [项目目录前置条件](project-documentation.md#项目目录前置条件)。目录尚未指定且无已绑定项目时，按 [首次使用引导](../SKILL.md#首次使用引导) 在最终正文先简要说明用途和开始方式，再用普通文字索取目录，得到答复后才创建问题文档；不得把目录问题或启动选择先写到当前工作目录、项目父目录或其他项目外位置。授权文档交互不等于授权助手选择存放目录。

1. 在已明确项目目录内的现有访谈文档或单独的问题文档中，完整写出本轮每个Q编号、问题、候选及简短差别（创作题默认三个A/B/C候选，Hyper3D操作分支按两个），注明可按题号和字母回答、自由补充、混选或明确委托。遵守原有问题范围、分组和事实项规则。
2. 正文只需简短说明本轮改用文档，并提供可点击的永久文件链接及作答提示。可同时打开文档面板；工具返回排队打开不等于用户已经查看。文档链接在此模式下是正式问题交付入口。
3. 记录`presentation_mode: document_due_to_session_constraint`、问题文档路径和当前触发原因；文档写好记`prepared_in_document`，实际发出链接后记`document_link_delivered`，不冒称`presented_in_chat`、用户已阅或已答。收到回答后逐题记录原话、采用值及未答项。
4. 恢复时保留题号和候选含义，只处理未答内容。新会话重新判断当前限制；不再受限时恢复正文为默认入口，不重问已回答的问题。

该方式服从实际会话规则；若文档交互本身也受限制，则不能用文件绕过。说明限制来自当前会话，不归因于用户或Skill，也不声称修改文件已取消会话限制。

历史文档记录某次出现过冲突，不证明之后的会话仍受相同限制。再次调用时以实际生效的上层指令为准；不得只凭旧记录继续宣称正文选项被禁止。文件同步成功也不等于当前会话执行限制已解除，完成说明须区分二者。

### 交互偏好与项目记录同步

用户对沟通形式的明确要求写入项目的交互约定或现有访谈文件，并由`PROJECT.md`、`project-state.json`索引；不用额外问卷确认已经说清的偏好。项目记录应能恢复以下信息：

- 用户要求：默认正文问题及三个候选、自由补充/混选/委托、禁用系统选择框；正文受限且允许文档时，以完整问题文档及链接交付。规则来源写实际用户话语或所采用Skill版本。
- 逐题状态：稳定`question_id`、候选原文位置、实际展示方式、用户原话、采用值及剩余缺口。题号与候选含义在正文和文档中一致，不因换轮重编号。
- 已答与未答分开：自由描述也可以构成有效答案，即使此前未完整展示三个候选；记录实际形式，不伪造字母答复。已确认题归档复用，其余保持open。
- 恢复入口：用户说“继续”时先继承已确认项，从未答题继续；不把纠正交互方式、维护Skill或“继续”当作接受所有推荐，也不重新询问已经确定的作品范围。

用户要求同步文档与Skill时，更新所涉项目入口、交互约定、访谈和状态，以及维护用发布源/安装副本；项目事实仍留在项目内。避免把某个项目的题号、推荐组合或临时会话冲突写成可发布Skill的全局创作规定。

### 候选与回答

候选针对当前故事、围绕同一决策维度，每项用短语加一句可感知的效果；推荐时说明简短理由，但不自动采用。不要把摄影、色调和时长绑成三个不可拆分套餐，也不要用三个近义词凑数。选项外统一提示“可以只回Q编号和字母，也可以混合、自己描述，或说这项由我决定”，无需第四个“其他”选项。已知项直接回显，不再提问。

路径、已有人名、原剧本、平台实际能力等事实只索取真正缺失的信息，不编三个猜测当事实；可以推荐时长或创作姓名，但应明确是待选方案。已有两个真实操作分支的MCP安装环节、阶段确认和错误处理不强制凑三个选项。

[Hyper3D 场景资产分支](hyper3d-scene-assets.md) 的建模方式、生成范围、质量各提供两个实际选项，允许自由补充，不套创作访谈的三选项配额。严格按“选 MCP → 验证安装与连接 → 预估对象并同轮给范围选项 → 选择质量”推进；已有答复直接继承，连接检查不是新增创作题。正文受限时完整写入项目问题文档，候选含义和已答记录保持一致。

简短示例（每题候选按用户题材改写）：

```text
Q01 这次作品的范围？
A. 独立短片：本次讲完一个完整事件。
B. 连续剧情的一章：沿用世界和人物，后续继续。
C. 暂先做试片：先验证一段，系列安排之后确定。

Q02 镜头的稳定程度偏好？
A. 平稳观察：固定或平滑移动，便于读清空间。
B. 轻微手持：有真人持机感，整体克制。
C. 随情绪变化：平静时很轻很慢，紧张时逐渐加大加快。

可简回“Q01B，Q02C”，也可组合、自由补充，或指定哪些题由我决定。
```

同一Q编号的选项一旦交付，不在用户回复前改义；记录实际候选文本、用户字母/原话、解析后的采用值与范围。区分`prepared_in_document`、`presented_in_chat`、授权文档模式下的`document_link_delivered`及实际回复；文档链接交付不等于正文展示、用户已阅或已答。只说推荐或工具返回排队打开，也不能冒充完成交付。用户混选时落实到具体段落或强度；只有冲突会改变结果时才补问。未回答不是接受推荐，委托只覆盖用户指定的题目。

解释连续字母或字母与自由回答混合输入前，逐题对照原候选，不凭记忆转换采用值。明确题号的自由补充覆盖该题候选，其他答复仍按实际题序对应；不能把更正当成新增题而导致后续错位。回显与原答复不一致时，当轮纠正现行记录，保留纠错来源，不要求用户重答已清楚的内容。

每轮围绕一个决策组，通常4–6个相关问题，按信息量增减；这不是最低题数或总题数上限。先展示已知内容，再问剩余项。不要让用户选择骨骼、坐标、修改器或内部JSON。回答存在依赖时先问上游，未获答复时只推进不依赖答案的整理。

“你来定”按上下文记录范围：对人物关系的委托不等于委托摄影色调，更不等于取消静态模型确认。明确“整个创作都由你决定”可以由助手提出完整方案，但仍展示采用结果；阶段查看点按 [确认规则](production-approval-gates.md) 执行，不用委托臆造用户满意。

## 开头先确定项目与本轮范围

先按 [项目目录前置条件](project-documentation.md#项目目录前置条件) 明确本次项目文件夹；首次裸调用使用主文件中的简短引导，介绍后只询问必要的目录事实，尚不展开创作选择或写启动文档。已有明确目录直接复用，目录答复不冒充后续创作题已获回答。目录明确后的首次项目记录保存该答复来源。

新项目先问清：这是独立短片还是连续剧情的一部分；用户已有的是梗概、部分剧本还是完整剧本；本次要制作哪一章/哪一场，是否需要创作尚未写出的内容。信息已在用户输入中明确就登记，不机械增加一轮。片段时长、整剧规模和单次生成时长分别记录。

已有目录先按 [项目文档](project-documentation.md) 读取入口、章节进度、相关人物/世界观和摄影色彩偏好，再说明已写与已制作的范围。本轮任务已明确就执行；范围不明时只问一题，按实际记录给三个可行方向并允许自行描述。不能把“第二章已有剧本、还没做视频”说成“需要续写第二章”，也不能把本段交付当成全剧完成。

## 三组访谈：每项必须有出处或待定状态

不是每个项目都逐字问完；已提供的信息标为已知，无人物/无声音等不适用项写明依据。对只有一句故事梗概的新项目，不能跳过第二组。

| 组别 | 需要明确的内容 | 可用的普通文字问法或方向 |
|---|---|---|
| 一：故事与人物 | 项目类型、已有剧本范围、本次章节/场次、续写与制作边界 | 这次作品是否属于连续剧情，本轮希望处理哪一部分？原剧本哪些内容已有、哪些允许创作或修改？ |
| 一：故事与人物 | 用途、观众、类型、最终媒介 | 希望像写实短片、动画、广告、MV还是其他形式？希望观众看完最强烈的感受是什么？ |
| 一：故事与人物 | 必留情节、结局、禁止改动、主题 | 哪些事件和先后不能改？结尾是揭示、留白还是别的方向？ |
| 一：故事与人物 | 人物姓名/固定称谓、关系、动机、性格与说话方式 | 主角叫什么、彼此什么关系、为什么做这些事？没有名字可以由助手提出候选。 |
| 一：故事与人物 | 时间地点、时代、现实程度 | 场景在什么时间和环境？表演与事件偏日常可信还是风格化？ |
| 一：故事与人物 | 总时长、画幅及范围 | 成片多长、横竖屏？交付参考视频和提示词，还是还要协助生成与剪辑？ |
| 二：摄影与美术 | 视觉风格、参考作品及具体借鉴点 | 是否有喜欢的影片/画面？借鉴它的镜头、光色还是表演，不默认复制全部。 |
| 二：摄影与美术 | 相机稳定程度和手持强度 | 固定/平稳移动、轻微手持、明显手持、强烈主观晃动；在哪些段落启用？ |
| 二：摄影与美术 | 长镜头与剪辑偏好 | 一镜到底、长镜头为主、长短结合或较密剪辑？有不希望出现的切镜吗？ |
| 二：摄影与美术 | 景别、视点、构图与空间感 | 偏近距离人物体验还是宽景空间关系？是否喜欢主观、过肩、中心构图或留白？可交由助手细化。 |
| 二：摄影与美术 | 色调、饱和度、明暗反差和肤色 | 偏冷、暖、中性或冷暖对照？低饱和还是鲜明？暗部保留到什么程度？ |
| 二：摄影与美术 | 主光来源、质感、景深及画面禁用项 | 自然光、现有灯源或明显造型光？清晰真实、颗粒粗粝还是柔和风格化？ |
| 三：声音与制作 | 对白、语言、表演与反应停顿 | 有无必须保留的台词？口语还是风格化？哪些时刻希望留出沉默？ |
| 三：声音与制作 | 音乐、环境音、关键音效、字幕 | 希望音乐参与节奏还是主要听环境和动作？是否需要字幕/旁白？ |
| 三：声音与制作 | 人物、场景、关键道具现有资产 | 已有图、只有文字设定还是都需要准备？角色图为成片身份，结构图为建模。 |
| 三：声音与制作 | 生图方式、参考片来源、生成入口 | 谁来生成资产图？最终用哪个平台/模型/入口？已有明确能力直接记，未知限制在分段前核实。 |
| 三：声音与制作 | 负载、交付和内容边界 | 沿用用户已给的电脑负载要求；涉及强暴力等题材时只补确实影响表达尺度的偏好，不例行增加无关问卷。 |

问完一组就把用户原话、解释后的采用值、明确委托范围和待定项写入当前项目记录，向用户给出短回显和文档链接。不得把推荐项写成用户已选；无答复仍为待定。具体文件与表格见 [文档模板](production-document-templates.md)。

## 帮用户选择，而不是替用户省略选择

下表是选项设计素材，不是已经向用户问过的问题。对每个待定摄影或色调问题给三个有实质差别的短方案，分别解释观感和取舍。例如稳定程度的三个候选：

| 摄影方向（独立可选） | 观感与取舍 |
|---|---|
| 平稳观察：固定/平滑移动 | 容易观察站位和反应，紧张可来自等待 |
| 轻微手持：克制的人手持机感 | 有临场感，同时保持关键事件可读 |
| 情绪驱动手持：由轻慢逐渐转为强快 | 用幅度和频率表现情绪变化，具体分段记录 |

镜头长度另问，可给连续长镜头、长短结合、短镜头为主三个方向；不能把选择手持当成接受长镜头。色调另从中性自然、低饱和偏冷、偏暖柔和、冷暖对照等方向中选取或改写三个适合本故事的候选，结合地点、主光与肤色说明。用户可自由描述并跨题组合，不将手持绑定冷色或将惊悚绑定快切。

将采用的方向落实为 `screen-language.md`：媒介、摄影视点、景别偏好、相机运动、手持强度和启用范围、镜头长度策略、色调/光线/质感、声音原则、例外及来源。最终电影美术与 Blender 中性识别色分开。风格不能只写“电影感、紧张、好看”。

## 从访谈到可修改的方案

1. 根据访谈汇总创作简报、具名人物，并在同一次方案回复中给出当前制作范围的完整剧本、分镜表和摄影色调说明。用户未另行要求拆开时，不先交剧本并停下来等待，再把分镜推迟到下一轮。已有批准剧本直接沿用，不为配表改写原文。
2. 分镜表必须主动逐镜展示当前范围；不能让用户追问才给。较长作品按已选章节分批，同批剧本配同批分镜，不能只给“11镜头已完成”或文件路径。每镜含时长、景别/机位、构图、主体动作、运镜与手持、情绪/信息落点、声音/切点和色光。完整表另存文件便于按镜号修改。
3. 随表解释本段如何铺垫、触发、留反应和收束，以及摄影偏好如何进入镜头。长镜头按镜内节拍列子行，注明“不切镜”；没有镜数或景别种类配额。
4. 允许用户对剧本与分镜一次性反馈和确认，分别记录已展示范围；用户只认可其中一项时不扩大为另一项也获认可。修改时同步受影响的剧本、摄影与分镜。方案认可后进入资产与制作，静态模型仍单独展示；见 [阶段展示与确认](production-approval-gates.md)。

对需要互动的关键动作，书面动作设计写清触发、对象、接触/操作、反应、结果和下个动作的条件。Blender 默认转译为整体关系与道具变化；分镜中若驾驶、持物等需要看清手与物体接触，按 [简化手部IK](contact-hand-ik.md) 标记采用范围。跑步、打斗等激烈动作仍不自动增加手部编排。

## 节奏与记录

项目层保存稳定摄影与色彩原则；段落层保存总体起伏；场次分别记录信息释放、表演能量、相机能量、剪辑密度、声音节律；镜头层写实际时间与例外。“慢/快”不自动控制全部层面，上一场的速度也不自动继承到下一场。

用户认可模型与动画后完成视频及提示词，不追加 AI 审片；后续生成偏差按身份、剧情、镜头、色光或声音定点修改。前期详细访谈不成为已认可项目重走全流程的理由。

## 认证与迁移边界

Gateway 的 `FG_AUTH_MODE` 与 Web 构建时的 `VITE_FG_AUTH_MODE` 支持 `platform|native`，未设置保持平台模式，两端需一致。原生模式仅放行 `open_ai_canvas_session` 会话 Cookie，不复制或透传旧 FG session；浏览器写请求仍须通过可信 Origin 校验，公开认证路径不豁免 CSRF。身份、角色与 disabled 状态以 Go `users` 为准，旧 `fg_accounts` 映射不能授予额外权限或恢复禁用账号。

账号迁移保持 UUID 与资源 owner 不变，默认 dry-run；显式 `fg-scrypt$` 仅兼容迁入的 FG 密码，不改变已有 bcrypt。迁移不复制旧 session、不迁移 groups；synthetic PostgreSQL 已验收 dry-run/apply、幂等、冲突拒绝与实际登录，2026-11-06 另按授权迁入两个本地旧站库共 3 个用户并保留邮箱验证/创建时间，不表示生产账号或会话已切换。完整 Cookie、CSRF、密码与离线迁移合同见 [HTTP API 合同](/docs/backend/http-api#fg-双认证模式与账号迁移)。

原生网页 Support Bot 仍是未接入功能：前端只显示 Alert，不提交、读取或监听对话；Gateway 返回明确 503，不向 Next 主站发送问题。该限制不改变默认平台模式，也不代表机器人迁移完成；验收缺口见[待测试](/docs/progress/pending-test)。

## 工作区数据归属

FG 的故事与项目及其画布面向公司成员共享。普通成员之间的自由画布、未共享项目和素材按所有者隔离。Go 后端启用 `CANVAS_FG_TEAM_WORKSPACE=true` 时有既有管理例外：`fg_accounts.platform_role=superadmin` 可以管理 `user` / `member` 所有者的私人项目、画布和媒体；`admin` / `superadmin` 所有者不属于该管理范围。未启用团队模式时仍仅按所有者查询。

native 模式将 Go `users.role=admin` 映射为上述 `superadmin`；Go 普通用户保留既有 `user` / `member` / `admin` 标签，陈旧 `superadmin` 标签不能提权。低权限 `admin` 标签只保留既有可见性边界，不使普通用户取得 Go 管理员权限。这是原有团队授权规则，不是本轮新增授权。

后端对画布列表、详情、保存、版本记录、资源及资产查询应用所有者或共享故事项目范围。广告网关对列表、打开、删除、恢复、清理和预算预留检查所有者。旧广告协作者记录不再授予访问权限；团队协作使用故事与项目。

成员主动发布的公司公共素材仍可通过公司素材库使用。独立广告工程、系统管理、公司账务核销和公司音乐制作队列分别按其授权路径处理，不能将上述 Go 管理范围视为绕过所有接口归属检查的通行证。

自由画布列表默认仅显示自由画布，可切换到故事与项目；分类在服务端分页之前执行，浏览器项目查询缓存包含当前用户 ID。

画布所有者可以主动创建分享链接。链接持有人可查看分享的节点、连线和媒体；登录后可选择「复制到我的画布」。服务器复制公开快照以及独立媒体对象，以复制者身份原子保存私人画布和素材库记录。副本不关联原故事项目，不携带原作者聊天、任务状态或渠道密钥。

停止分享、链接轮换或过期会阻止新的查看和复制。已经成功保存的副本仍属于复制者；编辑副本不修改原画布，原素材移除不影响副本。传输失败或传输期间撤销分享时，不发布半完成的画布，并清理本次未完成复制创建的媒体。

复制入口是 `POST /api/public/canvas-shares/{token}/copy`，要求当前登录用户和可信来源；公开路径名称不使写操作变成匿名操作。分享的读取只开放准确的分享路径及 SPA 静态脚本，普通私人画布和素材接口仍需归属检查。

验收需分别检查管理员之间隔离、普通成员之间隔离、superadmin 对 user/member 的管理范围，以及共享故事画布的读取和保存，不能一概断言跨用户访问均应 404。本轮隔离实例已确认成员不能读取管理员私人画布/原始资源、superadmin 可以读取 user 成员画布，低权限 admin 标签的画布排除在管理范围之外；共享故事与历史业务数据仍需另行验收。健康接口成功不替代这些检查。

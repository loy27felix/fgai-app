# FG 1.4.23

The 1.4.22 release did not close the end-to-end result-import gap. English language policy had a second speech parser that classified action sound and timing labels as spoken content. Reference-count rejection in the result parser could run before the new reference-selection dialog, and the batch UI did not call that dialog. Recovery existed only inside the chapter editor and could be skipped after a local attempt; the storyboard workspace exposed no durable recovery action.

Both tabs now display the same persisted-result panel. It distinguishes incomplete batches from completed output awaiting import, exposes errors beside the retry action, and never submits another generation. Existing shots require explicit replacement confirmation; source edits after task submission stop recovery. The previous automatic storyboard recovery loop is disabled in favor of this visible, reviewed action. Character extraction recovery retains its existing behavior.

All three write paths read the workspace back and compare returned shot identities/count before reporting success. Imported revisions retain task/batch identity and expected chapter row count. A recently edited manual placeholder is no longer evidence of a completed import. A later collaborator's verified import is preserved without expanding the account's private task visibility.

Reference overflow is reviewed after parsing. Stale IDs are flagged for user review with current project candidates, and current valid references remain capped at six. No actor is automatically removed to satisfy this cap. English prompt guards in the native web and gateway remain byte-equivalent and continue rejecting actual script changes.

Verification included a failing regression before the English parser fix, rendered pending-result panels, import/write/read-back integration seams, concurrency and changed-script refusal, and scoped in-memory replays of the affected real result sets. With explicit user authorization, normal owner business APIs restored four chapters (8/4/8/7 rows), and read-back verified dialogue, prompts, asset relations and unchanged source text. No paid requests, credential export, raw creative-content files, schema changes or new backups were introduced.

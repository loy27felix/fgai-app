# FG 1.5.8 上游适配

同步范围：上游 d77e977a 至 0a6f7c4d（v1.7.3及其后修复）。

## 用户可见能力

- 媒体生成分排队、生成、保存阶段展示；页面等待中断时可重新查询原任务，不等于重新生成。
- 结果下载有持续进度时最多15分钟；90秒没有任何进度才中止，失败原因区分停滞与超时。
- 取消用户手动补保存的累计3次上限；保留一分钟冷却、并发幂等、归属与退款检查，不增加自动重试预算或重新调用生成。
- Agent 右侧停靠、回复选项、个人记忆文件和修订、技能自动发现与推荐安装。
- 小说制作流水线的精修画布投送、采用结果、并行出片、按章节分集和参考图引用。
- 用户分组和多币种模型计价。旧用户仍属默认组，默认倍率1、渠道范围沿用已有开放范围。
- 插件支持素材上传、幂等交单、分离回查；增加 WAN3.0 转接，更新 xAI 视频结果解析和 Pi 图片批次补送。

## FG 保留合同

FG 短剧 `/projects` 与上游制作流水线 `/drama-pipeline` 分开；保留角色换装、原文台词核对、个人费用、广告、文档上传和服务端对话删除。普通用户只能查看自己的数据；原有登录和管理员路由守卫保留。

FG 已发布的1–78号迁移名称、校验和、顺序保持不变。上游75–77追加映射为FG79–81，依次增加分组货币列、记忆文件技能发现、记忆修订字段。新增列和表不重写既有项目、账单、渠道价格或模型配置。

按用户要求下线推广中心、超级综合工作台、旧版超级小说转视频（ArcReel），移除前端页面、导航与生成入口，旧链接返回410。停用对应的用户运行容器创建逻辑，保留已存项目与持久卷。共享广告、语音能力和上游 `/drama-pipeline` 仍保留。

同样移除管理中心的支付充值、积分运营、兑换码以及对应旧链接和公开操作接口，保留历史积分账本和订单。FG 实际制作费用、个人费用、供应商对账和原作品保存恢复接口继续保留。

## 存储故障

本机灾备失败的流式tar此前会遗留payload，清理逻辑又只处理完整备份，形成重复残留。修复只删除本轮生成但失败的state归档，保留失败清单；历史清理只针对已结束、超过一小时、未成功登记且无硬链接的失败tar，并保留每个来源最新失败样本。成功备份、SQLite文件和运行数据不在该清理范围。生产守护任务始终保持运行。

## 对账查询开销

费用匹配视图先为每个可计费请求展开并去重引用键，再按模型和引用键关联流水，避免对同一模型的流水反复解析请求 JSON。保留原本的多来源 OR、同名歧义排除、人工核销和用量回退语义；JSON 字符串、数组、对象的键存在判断与旧视图一致，数值等非字符串元素不会误匹配。人工合成数据双向集合比对通过；生产使用同一快照比对匹配集合摘要，未改动账单、金额或用户记录。

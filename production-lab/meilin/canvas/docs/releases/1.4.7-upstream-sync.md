# FG 1.4.7：资产筛选与画布同步

## 用户操作

- “自动筛选与批量生图”默认保留角色和场景，道具按章节原文次数、跨章使用及剧情重要性给出推荐和理由。普通一次性道具默认不选；关键线索与连续性道具即使只出现一次也保留。旧候选缺少语义标记时使用文字规则，可人工调整。
- “仅确认所选”不调用模型；“批量忽略未选道具”软忽略候选，不删除原素材。付费生图仍需用户确认 Prompt 和报价。
- 资产卡片显示排队、生成、保存和失败，重进后从服务端安全摘要恢复，完成时刷新。
- 更换图片增加“本资产历史版本”，选回旧图通过原有绑定流程形成新版本。
- 图片上传按文件头识别真实尺寸，不再拿画布显示尺寸当原图像素；预检错误指出第几张图、实际尺寸及具体限制。不自动重试旧任务或产生费用。

## 验证边界

前端完整测试有 2708 项通过、9 项失败。这 9 项均在修改前的独立 HEAD 副本复现，涉及 Windows Shell/换行及原有保存、观察订阅断言，不把本次记录写成全套通过。

新增专项覆盖普通/关键/重复道具、别名计数、任务状态、重试优先级、旧图保留、跨用户隔离及真实图片尺寸/字节重放。后端 Windows 全套遇到 Unix 权限、目录同步和插件平台依赖，不把这些结果写成后端全套通过。Linux 验证与部署结果由发布核验记录补充。

未进行付费图片或视频生成；未自动确认用户项目候选，未重新生成或替换已有产物。

最终校验：本地 TypeScript、必需前置门禁（63 项）、资产专项（20 项）和 `build:fg` 通过，9 个入口资源路径检查通过。Linux ARM64 隔离测试覆盖 app、handler、repository、canvas、assets、protocol、prompts，合计 1627 项通过。其中 app 首轮两项因测试基础镜像仍指向旧插件目录失败，显式指定本次插件目录后两项复验通过；发布镜像需一同复制新协议包。未将 Windows 全套或前端已复现的基线失败描述为通过。

浏览器验收受当前 Work 的“浏览器访问关闭”设置限制，无法进行实际点击验收；页面入口与回归以真实源码测试和构建为依据。

上线只读核验：实际短剧项目返回 6 个资产图片版本、3 张不同图片，12 条资产生成任务能通过安全摘要关联，未返回私密任务输入。另补普通导入图片的历史兼容：缺少 representation 的当前图片也能显示；首次换图时在与新版本相同的事务中保存旧图关联，原 Prompt 保持不变。专项回归通过。

# NAS 恢复和删除规则 · FG 1.2.7

媒体原件保存在 NAS。FG 主数据库、广告活动 SQLite 数据库保存在服务器的 Docker 数据卷；它们另有 NAS 备份。浏览器缓存不承担唯一副本。

2026-10-04 的广告恢复失败由 Docker 中旧的 NAS 绑定引起：主机 SMB 挂载和就绪标记可见，旧 backend/adcraft-api 容器中的绑定返回 Not a directory。新容器同一只读挂载可见标记。核对零活动任务、两份 SQLite 一致性快照、主机 NAS 标记后，仅重建第六模块 backend/adcraft-api，并重载第六模块 TLS；原五模块的镜像、启动时间未被本次操作改变。

NAS 主机监督任务当晚再次恢复 SMB 挂载。第六模块维护任务之前只重启 backend，无法刷新绑定，且未覆盖广告服务；现已按每分钟维护周期探测两个现有容器。新挂载探针读写成功且 FG/Agent 无活动任务后，先保存广告 SQLite 一致性快照，再重建失效的第六模块容器。与部署共用维护锁。该任务不挂载 SMB、不读登录凭据，也不操作原五模块；它不能消除 NAS 网络或主机挂载本身的中断。

## 删除

- 删除画布节点只移除引用，不能同时删除其他工程或素材库正在使用的文件。
- FG 素材回收站按资源策略到期清理；资源删除队列持续重试失败的物理删除，共享引用和历史恢复引用受保护。未绑定的完成上传有 24 小时清理窗口。
- 广告项目删除后保留 30 天。网关每小时复查归档时间和活动任务；与恢复操作共用行锁。内部广告 API 再检查原生 Agent 任务、进行中的 HTTP 请求和 NAS 标记，只删除该工作区独立 NAS 目录。
- 清理成功后登记 purged_at，回收站不再提供恢复。服务器留存小型工程数据库与账单、任务记录作为审计数据；本地清理标记禁止旧快照再次写回 NAS。公司素材原件和其他项目文件不在此目录内。
- NAS 不可用、任务仍在运行、清理失败时不会标记已清理，下一小时重试。没有达到保留期的真实工程不会因升级而删除。
- 广告 SQLite NAS 快照采用一致性备份、校验、原子覆盖，仅保留当前快照。部署前数据库备份另计，不是每分钟新增副本。

## LibTV

配置与开放导入是两个开关。管理员验证不要求先开放导入。上游错误只回传本系统生成的诊断和数字状态码，不回传响应原文或 Token。LibTV 拒绝登录不会变成 FG 的 HTTP 401，以免错误退出 FG 账号。

后台验证支持分享链接并提取 projectId。媒体会先复制到 NAS，再保存画布结构。本次实际导入发现 CDN 的 PNG 和 MP4 返回 text/plain；已按已知媒体文件头识别类型。已归档的同一幂等资源在重试导入时就地修复 MIME，保留资源 ID、原文件和容量计数，不重复下载。

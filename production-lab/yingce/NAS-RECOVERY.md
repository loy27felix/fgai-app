# 更换 NAS 后恢复第六板块

本清单针对宿主机已挂载新 NAS、FG 数据仍在恢复的情况。入口继续使用原来的 3000 端口。

## 恢复期间

1. 保持旧工程、数据库和 Docker 私有状态卷。不要因空白页或 503 新建同名空工程覆盖旧工程。
2. 不执行生成、删除、回收站清理、工程快照回写或自动归档验收。广告工作区打开后可能启动定期快照，因此也要等数据恢复完整。
3. 构建、单元测试和静态资源发布使用 FG 本地构建目录，不挂载恢复中的 NAS。新镜像准备好与线上业务恢复分开记录。

## 数据恢复完成后

由 NAS 恢复负责人确认 FG 数据已完整恢复，再按顺序操作：

1. 对比宿主机和现有容器内的 `.fg-studio-nas-ready`。宿主机可读而容器缺失，表示旧容器仍绑定旧挂载；普通进程重启不能据此证明重新挂载成功。
2. 校验 `yingce/.settings-key` 为原 32 字节密钥，并能解密现有渠道凭据。只报告校验结果，不打印密钥、明文凭据或完整 Docker 环境变量。禁止创建替代密钥。
3. 检查没有正在运行的付费任务、待执行的资源清理任务或同事正在使用的工程，再用当前正式 Compose 配置逐个重建需要重新挂载的 FG 后端、广告服务与用户运行环境。保留原镜像回滚记录、数据库卷、私有状态卷和账号隔离网络。不要使用 `down -v`、全局清理、Docker 虚拟机处理或删除 NAS 内容。
4. 综合与小说用户环境必须先核对各自用户目录和工作区标记。沿用已有私有状态卷，不直接运行会创建默认目录、配置或快照的全量初始化脚本。
5. 检查所有相关容器实际读到新盘文件，再验证普通成员与管理员登录、公司渠道、模板、广告和小说入口。
6. 按现有工程执行保存并读回、视频播放、任务提交与结果归档验证。真实生成采用已授权的最低价规格，禁止对结果不明的旧请求自动重发。

## 现象与判断

| 现象 | 需要核对的证据 |
| --- | --- |
| “系统渠道不存在或已停用”但数据库渠道启用 | 原密钥是否在容器里可读、是否能解密原凭据。不能仅凭错误文案删建渠道。 |
| 综合工作台模板空白 | 实际模板接口是否返回 503。模板资源随镜像打包，空白不代表模板或用户工程被删除。 |
| 广告入口提示 NAS 不可用 | 广告容器里的 NAS 标记与宿主机是否一致；恢复未完成时不启动旧工程快照回写。 |
| 小说入口反复准备或素材不可读 | 用户隔离运行环境、网关映射、用户工作区目录及实际素材文件是否均可用。 |
| 灵感库部分来源更新暂缓 | 核对各来源上次成功时间与外部请求错误。已缓存条目保存在数据库，不能因此清空缓存。 |

故障修复与验收状态记录在 [待验收清单](canvas/docs/content/docs/progress/pending-test.mdx)。

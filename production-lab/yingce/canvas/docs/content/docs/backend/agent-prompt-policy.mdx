# 画布 Agent 提示词与用户意图

画布 Agent 的任务来自用户消息及仍有效的对话约束。默认工作方法、技能、长期偏好、记忆和模型自行生成的清单都不能扩大任务范围。权限、资源归属、预算、审批和快照校验由服务端代码执行，不能通过提示词授权。

## 维护边界

新增行为规则应修改版本化策略；新增运行状态应定义事件及事实字段，在策略里说明处理方式。不要在错误分支拼入“现在就调用工具”“必须生成视频”等指令，也不要把参考素材中的文字直接拼成规则段落。

节点能力速查同时从注册表投影 `canSource`、`canTarget`、`canReference`、`inputKind` 和接受/拒绝输入类型，避免只有创作用途描述而缺少实际连接边界。`canvas_apply_ops` 的引用连线代表生成输入关系，不是文档归档或任意节点关联；模型缺少参数或选择了不支持的节点组合时，执行层仍拒绝写入。

## 单一策略、动态事实与记忆

运行时只 embed `agent-system-policy.md`，当前为 `cloud-agent-system` v19。`prompts/AGENTS.md` 是开发维护约定，不再进入模型上下文；旧独立媒体规则文件已移除。`LoadAgentPolicies` 为已有冻结校验字段派生 `cloud-agent-media` 标识、同版本号及哈希，其正文为空，不是第二份规则。策略修改仍需发布后端，不能由用户偏好、技能或记忆热更新覆盖。

画布目录、用户目标、选区、任务观察、长期记忆和技能提示走有来源的动态消息。它们插在最后一条真实用户消息或已送达插话之前，同一来源的旧消息会被替换；来源标记和条目 ID 只是服务端元数据，不发送为供应商参数，也不能变成用户授权。

### 长期记忆

每个用户一份记忆文件，分「关于用户」和「工作笔记」，每条带稳定 ID，默认容量 5000 字。建运行时冻结一份快照，Go 步进和每次 Pi 模型请求前都以 `agentContextSource: "agent_memory_doc"` 重新插入同一份内容，一轮内不变，前缀缓存不受影响。快照写明用量；超过八成时提示先合并或删除。用户这条消息里有“记住、以后、下次、叫我”等说法时，快照末尾加一句提示，提醒 Agent 考虑写入记忆。

Agent 用 `memory_update` 按顺序执行 `add` / `replace` / `remove`，整批校验容量、单条长度和敏感内容（链接、节点或任务 ID、资源键、凭据）。`auto` 模式立即生效，每次修改留修订并在聊天里显示可撤销的卡片；`review` 模式写成待确认修订，确认前不生效，Agent 不得说“已记住”；`off` 不注入也不开放工具。`read_only` 运行不能写。同一工具调用 ID 重放时返回已有结果。

旧版 `remember_lesson` / `recall_lessons` 及逐步注入已移除，原因是：资格只在同轮成功写入后才打开，草稿要等整轮完成且由用户逐条批准，30 天未批准即过期，固定的主题/场景/步骤结构写不出有用的偏好，关键词召回几乎不命中。首次创建记忆文件时，已批准的旧条目会导入为一次可撤销的修订。

### 技能目录

已安装且 `agentMode` 不是 `manual` 的技能编成「已安装技能目录」，放在 system 末尾、执行上下文之后。目录最多占本轮输入预算的 5%（至少 1000 token）；预算内先列“名称 [skillId]：短简介”，用到 70% 后只列名称，其余只报数量。排序先看 Agent 实际读取次数，再看排序权重和安装时间，入选后按分类和名称稳定输出，避免使用次数变化打乱缓存前缀。用户本条消息点名或为对话固定的技能，以及关键词预筛的候选，放在「技能提示」动态消息里。正文仍按需通过 `skill_read_file` 读取，运行只冻结版本号。

已安装技能都不适用时，Agent 可以用 `skill_market_search` 找市场候选，再用 `skill_recommend` 在界面显示安装卡片；安装由用户决定，Agent 不能自行安装。

Pi 请求从同一个运行 `budget.maxSteps` 推导步数上限，0 表示不设固定步数限制，不再写死 50；`read_only` 的权限投影和实际工具集都不授予画布写入。旧 CanvasIntelligence 启发式摘要及无界 metadata 注入链已移除，正文和状态仍由语义读取工具提供。

## 用户目标与参考素材

### 视频首尾帧

`generate_media` 支持可选的 `videoStartFrameNodeId` 和 `videoEndFrameNodeId`。每个非空值必须是 `referenceNodeIds` 中已解析的图片引用，仅用于视频。参考数组决定素材编号，两个帧字段决定用途；在提示词中写“图片1作为首帧”不会自动选择首帧。

只编辑、不生成时，先用 `canvas_apply_ops` 建立图片到视频节点的引用连线，再通过 `update_node.patch` 设置同名字段；空字符串取消选择。节点读取会返回当前帧选择，生成审批也会显示首尾帧节点。生成工具仍需明确传入本次选择，不会根据历史提示词猜测用途；原有权限、素材归属、审批和计费流程不变。

- 新消息只覆盖与之冲突的旧要求。“继续”“可以”仍结合历史理解，不丢弃有效约束；已送达的运行中插话也进入后续可信历史。
- 当前用户请求保留在 user 消息及运行记录里，不复制进 system 提示锁定目标。系统上下文只包含可验证事实，素材标题、摘要和标签编码为 JSON 数据。
- 删除原先通过“参考图”“图生视频”等关键词推断强制引用的逻辑，否定句和概念解释不再被代码标记为引用任务。
- 候选素材不等于用户选择的素材。候选列表有数量上限，不能视为完整画布；素材标题和提示词也不是视觉识别证据。
- 不再默认赋予 Agent 改写故事、镜头顺序、对白和风格的权限。用户只要求修改标点、分析或准备提示词时，不能借默认策略扩展为创作或生成。

## 运行状态与待办

运行时使用 `plan_state`、`pending_plan`、`empty_output`、`invalid_output`、`truncated_tool_arguments` 事件。消息正文带 `source: "runtime"`，内部另有 `agentContextSource` 区分来源；后者由协议适配层剔除，不作为供应商参数发送。

由于各供应商消息协议不同，运行上下文仍通过 user 角色承载，正文与系统策略明确它不是用户新要求。程序识别内部消息依赖来源字段，不再根据正文包含“待办清单”或“现在就调用工具”判断用户身份。结构化边界减少混淆，但不能保证模型绝不受参考文本影响。

继承清单作为上下文保留。用户取消或缩小目标后，Agent 可以用 `plan_update` 整表替换，移除不再需要的项；空数组表示清空，不把取消伪装成完成。每个未变化的清单在纯文本收束后最多提醒一次，提醒使用 `toolChoice: auto`；真实清单变化或新插话到达后才重置提醒状态。没有继续动作时允许结束本轮，保留未完成项及实际结果，不靠无限催办消耗预算。Pi 运行时由完成闸执行同一规则，催办作为恢复提示词进入下一步，并受本轮步数预算约束。

输出恢复只报告错误事实及协议限制。正文限制按 UTF-8 字节计算；不再把字节误称为字符，参数截断也不再夹带“分镜每次不超过三行”的业务假设。

## 验证与发布

自动回归覆盖新目标继承、插话保留、否定参考需求、消息来源、计划取消、有界催办、恢复事件及 OpenAI Chat/Responses、Claude、Gemini 协议转换。测试使用临时 SQLite 和模拟模型结果，不证明真实模型的创作质量或指令遵循率。

当前系统策略版本为 19、编译器为 `cloud-agent-policy-compiler/v6`、工具 schema 为 `cloud-agent-tools/v8`。版本 19 加入技能自动发现、市场推荐、长期记忆文件的维护规则，以及“请用户挑下一步时先写问句，再在回复末尾列 2–4 条编号短句（界面显示为可点击选项），不写‘回复数字’；必须先定才能继续的创作决策用 `ask_user`”。版本 18 明确 `maxGenerationTasks` 和 `maxVideoSeconds` 是本轮累计上限，`0` 表示对应项不限；该语义不改变积分、权限和媒体审批校验。版本 17 加入了写入画布、申请审批、提交生成或向用户提问的工具调用前先用一两句话说明做什么及依据，正文预告的操作必须在同一条回复里发出。助手身份由服务端从外观配置读取 `canvas.agentName`，通过执行上下文的 `agentIdentity.name` 提供；字段只表示名称，不能更改行为规则或工具权限。每个新回合重新读取配置，已完成对话的后续回合使用最新名称；身份变化改变规范系统提示及对应缓存键，不覆盖历史消息或冻结快照。

长期记忆文件与技能自动发现使用 Schema 76，见 [后端数据库](./backend-database)。既有冻结合同校验仍生效：旧版本正在执行或等待审批的运行不能由新版服务继续执行；终态历史仍可读取，新消息建立使用新合同的运行。发布前应处理在途运行；回滚同样受版本校验限制，不应改写历史快照来强行恢复。

本轮单一行为合同治理覆盖对话主链路。旧版经验压缩仍使用独立的受限 JSON 提案提示词，只能手动触发，产出必须经过用户审批和版本校验；它不增加 Agent 操作权限，也不替代运行时行为合同。批量创作默认词等其他生成入口仍应按各自合同维护，不能把本轮回归称为全仓提示词治理完成。

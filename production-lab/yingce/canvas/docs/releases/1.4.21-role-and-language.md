# FG 1.4.21

Role reference matching now uses confirmed aliases as well as complete asset names. A known on-screen character missing a usable bound photo, or an ambiguous alias without one explicit actor, prevents shot submission. The phone-screen/message-only distinction remains in force. Each new video artifact retains the submitted reference manifest (asset, version, resource, image index and usage), without copying media or credentials.

The original failure pattern was a narrative using a short character alias while only full titles were matched. The fix covers automatic association, individual video execution and batch preparation. Existing incorrectly generated videos are retained; selecting **重新匹配资产** repairs missing associations for review before a deliberate new generation. Reference-only names are excluded from the narrative coverage check. Model identity adherence still requires visual review.

Project settings add an opt-in production language policy, persisted in an existing `system_settings` entry per project. The native project access check runs before reads/writes; optimistic revision checks prevent lost settings. No schema migration, scheduled job or backup is introduced. English mode uses original English dialogue from bilingual source, never a new translation. New storyboard imports, rewrite output and shot video submission check the spoken words. Screen-language instructions propagate through protected native image template variables as well as ordinary prompts. Internal Chinese titles and production notes remain valid.

Existing projects default to source language. Saving the policy affects future tasks only, does not rewrite existing assets and does not trigger paid generation. Policy changes after preview require another preview. The original script is never changed; applying a rewrite restores uniquely matched English dialogue only with the user's existing Apply action.

Validation: native typecheck, role/reference/draft/batch regressions, chapter/recovery/voice regressions, gateway language authorization/versioning/task checks, release build. No paid generation used for tests. Production rollout updates native web, gateway, and root version metadata only; worker/database containers and all production LaunchAgents are preserved.

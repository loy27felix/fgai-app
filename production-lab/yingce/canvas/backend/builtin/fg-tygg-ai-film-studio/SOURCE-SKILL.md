# TYGG AI 影片工作室

规则版本：3.2.7。目标是围绕最终 AI 影片完成创作、视觉设计、分镜、资产和结构预演，再交付可使用的参考视频与完整提示词；不能将任务缩成 Blender 建模。支持独立短片及连续剧情中的指定章节/片段；本段交付不等于全剧完成。实际生成、剪辑与发布是否由助手执行，按用户约定分别记录。SceneSpec/硬件 Schema 保持 1.1，兼容旧项目，不把规则升级自动变成旧项目返工。

## 不可省略的执行约定

- **先明确项目目录，再写项目文件。** 按 [项目目录前置条件](references/project-documentation.md#项目目录前置条件) 复用用户已明确的项目目录；未指定且无已绑定目录时，先在聊天中用一句普通文字询问项目文件夹，得到答复后才创建或绑定。启动问题、访谈、状态及其他项目产物全部写入对应项目内，不把当前工作目录或多个项目的父目录默认当作项目根目录。文档问答同样遵守此前置条件，不能为询问目录先在项目外创建MD。
- **用户指定的风格先研究，首版预演即体现。** 明确指定影片、创作者、拍摄手法、风格或影像样例时，按 [指定风格参照](references/directing-story-and-editing.md#指定风格参照的前置研究与首版实现) 在首版相关分镜前研究。借鉴维度优先于默认拍法，并服从用户更具体的要求；将依据对应到镜头和时段，首版Blender落实相机、主体调度与剪辑节奏，不等用户再次提醒。已有适用研究可复用，来源和实现限制如实记录。
- **关键事实贯穿制作与交付。** 身份、空间、持物/接触、方向、动作起止与时间基准按 [现行事实同步](references/project-documentation.md#现行事实与历史快照) 维护，现行摘要保持唯一、历史通过版本链接追溯；按 [动作参照系](references/camera-and-action.md#动作语义参照系与可读结果) 解释人体与物体方向。用户纠正后同步所有受影响的现行材料，旧快照不能无说明地成为当前依据。
- **默认正文提问，每题三个选项，可自由补充。** 前期每个待定创作问题按 [互动共创](references/interactive-development.md)，默认把问题及三个简短候选写在聊天正文中，用Q编号＋A/B/C呈现；支持字母简答、混选、自由阐述或明确委托。推荐不能替代其余候选，已知信息不重问，事实输入不编造选项。仅当当前会话限制正文呈现且允许文档交互时，使用下述文档方式。
- **正文受限时交付完整问题文档，仍禁用系统选择框。** 项目目录明确后，按 [冲突说明](references/interactive-development.md#会话规则冲突的处理) 将本轮问题、各题完整候选及作答方式写入该项目内的文档（创作题默认三项，Hyper3D 操作分支按两项），正文简短说明改用文档并提供可点击链接，让用户查看文档后回答；此条件下已获授权，无需再次确认交互方式。正常会话仍由正文提问、文档同步记录。不调用 `request_user_input`、`request_user_input_async` 等系统问卷/选择卡工具，除非用户明确改变偏好；文档方式不代表取消会话限制或授权选择项目目录。
- **正文、文档与恢复进度使用同一套题号。** 按 [交互记录同步](references/interactive-development.md#交互偏好与项目记录同步) 保存候选原文、实际交付方式和已获回答，区分正文展示与文档链接交付；不把文件存在当作已阅或已答。用户说“继续”时只恢复未答部分，不重问已确认项，不把推荐当选择。同步有关项目入口、访谈与状态；临时会话限制单独记录，不当作新会话的固定限制。
- **先明确项目范围，再访谈或恢复。** 新项目先确定独立短片/连续剧情、本次章节、已有剧本范围及续写或制作需求，再按 [互动共创](references/interactive-development.md) 覆盖故事、具名人物、观看体验、摄影、色光、声音、资产与交付。指明已有目录时先读 [项目记录](references/project-documentation.md)，主动说明已写、已制作和未完成部分；已知信息不重问，委托不扩大范围。
- **剧本与分镜同轮主动展示。** 首次提交当前制作范围的完整剧本时，同时展示逐镜分镜表和摄影色调说明，附永久文件链接；不等用户追问，不先结束回复等待剧本确认才生成分镜。表内给出实际景别、机位、构图、运镜/手持、动作、时长、切点、声音和色调。用户可一次反馈两者；明确只看剧本时才按其范围执行。长作品只展开本轮选定章节。
- **静态模型单独确认后才做动画。** 按 [阶段展示与确认](references/production-approval-gates.md) 保存并展示静态场景，结束该轮等待对此产物的反馈。批准剧本、批准开始建模、笼统“你来定”都不替代静态确认。用户明确取消某个确认点时记录其原话与范围，已有同范围认可不重问。
- **人物默认圆柱＋球头＋简易弯曲骨骼，接触镜头按需加手。** 以空间、归属、接触和结果是否可读决定最小表达范围；新建人物按 [尺寸与弯曲标准](references/character-proxy-standard.md) 记录总高、体宽和头径，默认4根骨骼控制圆柱大姿态。驾驶、持物等确需看清手与道具关系的镜头，按 [简化手部IK](references/contact-hand-ik.md) 增加与上躯干绑定的低面手臂和掌块；这属于按镜头选择的结构表达，无需另行改选完整人体策略。跑步、打斗等激烈动作默认不做手部动画。静态阶段绑定，静态认可后才写动画；不默认建独立腿脚、肩颈、面部、手指或步态。详见 [代理合同](references/previs-visual-contract.md)。
- **新制人物设定图固定版式。** 左1/3为头部特写，右2/3为同一角色并排的正面、侧面、背面站立全身三视图。助手生图和交付生图提示词均执行 [人物图规则](references/character-image-assets.md)，成片提示词明确只参考身份与服装，不复制多视图排版或生出重复人物。
- **镜头变化服务于内容表达，镜内转弯默认圆滑。** 在方案与动画阶段按 [导演节奏](references/directing-story-and-editing.md#4-节奏层级整场节奏与切点) 联合安排对白、行动、揭示、反应与有效观看时间，再选择切镜、移动或保持机位；相邻主体不自动要求移镜。路径、朝向、速度和构图共同设计，用可通行的弧线与渐进视线完成有动机的转移，落点及时、停留可读，不以直角折线或密集关键帧制造顿挫。具体见 [联合路线](references/blocking-and-camera-paths.md)。
- **投喂正文从素材职责开始，保留有效结构。** 每项 `@视频N` / `@图片N` / 实际标签写明对象、采用维度和必要排除，随后写人物及道具、摄影与声音、按大体时段组织的动作与表演、连续性。无上传时给明确标注的计划编号及文件对照；使用 [参考提示词模板](references/reference-prompt-template.md)，不因局部修订重写已有效的顶部职责。
- **粗预演保留结构，角色按既定媒介与风格自然表演。** 按 [大体时间与自然表演](references/ai-video-and-asset-prompts.md#大体时间与自然表演) 继承镜头、空间、整体路线及关键事件关系；动作段补意图、对象、因果和结果，段内不逐秒编排关节或表情。打戏、文戏分别选择情境所需的表演线索；文戏在关键转折补出可读的表情变化、声音和倾听反应，区分谁发起、谁接收及镜头看谁，情绪由事件推动并延续。按 [人物对应与入画连续性](references/ai-video-and-asset-prompts.md#人物对应与入画连续性) 明确身份、声音及遮挡前后关系，保留局部动作自由。用户已验证有效的结构与自然度作为后续局部修订的基准。

**用户确认后进入交付，不追加 AI 复核。** 用户认可模型与动画即采用该版本；直接编写提示词并完成已经约定的视频导出，不重做碰撞、全片播放、导演审片或 Release。新写或修改的文字仍须就地核对当前素材、主体和动作事实，先解决已知冲突；这不构成重审已采用动画。必要导出是完成产物，已有同版本视频直接复用。具体分流以 [用户确认与交付](references/user-review-and-prompt-handoff.md) 为唯一依据。

**Blender 简化不等于成片细节简化。** 剧本保留完整表演设计；投喂正文选取关键交互、结果和符合景别的表演线索，不把导演或动画事件表逐项变成微动作命令。Blender 按镜头可见接触需求选用简化手部，不凭跑、抓、咬等动作词扩展成全身表演。参考正文限定简化手部只贡献接触位置、持物归属和操作时机；自然抓握、手指及激烈摆臂交给成片表现。完整高级动画仍须用户明确改变本项目代理策略；“动作更清楚”本身不构成此授权。

**资产同批准备、按用途使用。** 新建场景与关键道具所需结构参考图须可用、已登记并已认可；复用现有可靠参考，不为固定数量补图。前期确认已有的人物资产，缺少的人物图与场景/道具一起交付提示词或按授权生成。人物图服务于最终视频，不阻挡 Blender 中性代理建模和动画；两种就绪状态分开记录。

### 首次使用引导

用户仅调用Skill、尚未明确本次项目时，在首次最终回复的字符画下方使用以下简短引导，依次说明作用、合作方式和开始方法，不额外展开长篇功能清单或内部规则解释：

> 我可以帮你把故事想法做成剧本、分镜、人物与场景资产图，再通过 Blender 预演镜头和动作，最后整理用于 AI 视频生成的参考视频与提示词。
>
> 你可以从一句想法开始，也可以继续已有项目。我们会分阶段制作，你查看确认后再往下推进。
>
> **先告诉我项目保存在哪里。** 例如：“在当前文件夹新建‘夜归’”，或直接提供已有项目的路径。

用户已明确项目目录或具体任务时，复用已知信息，在字符画后简要说明当前进度和本轮下一步或结果，不重复完整介绍、不重新索取已知目录。目录仍缺失时可简短接住已给的故事想法，最后只索取必要的保存位置；示例名称不是用户已选目录，不据此自动创建。仅为询问目录时，不附加“Skill规则要求先明确项目目录”等内部条款说明；用户询问原因或实际权限阻碍需要解释时再说明。后续创作访谈及阶段确认按原流程执行。

## 工作方式

0. 按 [项目文档与连续制作](references/project-documentation.md) 先明确或复用项目目录，目录缺失时先在聊天中询问，不创建启动文档。目录明确后识别新项目、制作已有下一章、续写未写剧情、修改或分支；恢复入口、剧情进度和相关Canon，再回显当前状态与可执行下一步。用户本轮已明确任务时直接继续，否则只问范围缺口。
1. 按 [互动共创](references/interactive-development.md) 进行覆盖完整的创作访谈，使用 [文档模板](references/production-document-templates.md) 持续记录原始回答、明确委托和未决项，并给用户文件链接。确定具名人物、摄影风格与手持/长镜头偏好、色调光线和声音；已有答案只复用，不遗漏未问维度。平台能力按 [参考视频交付](references/reference-video-delivery.md) 记录，此时不查 MCP。
2. 有用户指定的风格参照时先完成有关研究，再按 [导演与剪辑](references/directing-story-and-editing.md) 同轮交付当前范围的剧本、完整分镜表和摄影色调说明，展示研究手法如何转为本片镜头；未展开的后续章节保留进度记录。已有剧本先登记原文与选定范围，不擅自改写全篇。长镜头内部节拍不是额外切镜。现实依据按 [研究范围](references/research-evidence-and-reality.md) 分级。
3. 形成制作方案时就地解决叙事、时长与空间冲突；按 [场次节奏合同](references/project-documentation.md#场次节奏合同) 分配动作、信息读取和结果停留，明确调时的来源与用途，不另设循环审查。按 [阶段确认](references/production-approval-gates.md) 明确本次展示的产物和下一步；创作委托不扩大成自动跳过未展示的分镜或静态模型。已认可的同范围决定直接复用。
4. 按 [图片资产流程](references/reference-image-driven-assets.md) 一次性交付必要场景、道具、缺失人物及已计划补图的提示词。人物按 [人物图准备](references/character-image-assets.md) 复用或设计。用户自行生图时创建缺失的同名占位 PNG；助手生成时按真实依赖保存成图，不创建占位。图片语言、文件语言和工具沿用用户偏好；没有指定时按当前可用能力提供适配方案。建模前只检查本次所需结构图就绪，人物图可同步推进。本批资产图认可后、Blender 建模前，按 [Hyper3D 场景资产分支](references/hyper3d-scene-assets.md) 先选择直接 Blender 或结合 MCP；选择 MCP 后检查安装与连接，通过后才预估对象并给出少量重点/中等数量的具名范围选项，再确定质量并生成下载。已有选择复用，不提前筛选、不重问。普通植被优先 Blender，MCP 聚焦非强交互的复杂静态形体；参数、无材质、资产版本与实例管理见该分支。
5. 确定进入 Blender 制作/修改时，按 [MCP 连接与安装选择](references/blender-mcp-setup.md) 轻量确认目标实例；正常直接继续，有缺失才提供安装步骤或助手安装配置两种方式。按 [结构预演范围](references/previs-visual-contract.md)、[场景结构](references/scene-blockout-and-camera-motion.md) 与 [执行规范](references/blender-mcp-execution.md) 小批次制作：空间拓扑/净空 → 可识别环境与道具 → 用户认可静态场景 → 镜头、主体和道具变换联合粗排 → 用户查看动画。采用 Hyper3D 时只在对应对象处使用已登记的生成资产，保留原场景关系与制作顺序，沿用原资产和性能规则，不新增逐资产审批。用户已直接查看认可即可，不另补审片图。
6. 静态确认后，多主体交互先按 [交互因果与状态](references/interaction-choreography.md) 确定目标、有效距离、各参与者状态与结果，再按 [尺寸与弯曲标准](references/character-proxy-standard.md)、[镜头与动作](references/camera-and-action.md) 和 [联合路线](references/blocking-and-camera-paths.md) 制作角色路径、整体朝向、圆柱骨骼弯曲与道具事件；分镜中需要可见接触的局部，按 [简化手部IK](references/contact-hand-ik.md) 制作。圆滑基础运镜与情绪手持分层；手持同时安排幅度和变化频率。完整肢体仅在用户明确改选策略时读取 [高级表演](references/animation-and-performance.md)。小批次保存，展示动画后等待用户意见。
7. 用户认可后按 [交付分流](references/user-review-and-prompt-handoff.md) 直接完成参考视频与 [完整提示词](references/ai-video-and-asset-prompts.md)。每个生成单位首部落实逐素材职责和具名主体对应，采用摄影、色调、剧情、声音及必要表演；动作按大体时间分段，段内自然衔接，具体写法与打戏/文戏示例见 [模板](references/reference-prompt-template.md)。分清计划 `@` 编号与真实绑定；不因未上传就改成只有语义占位的正文。材料未齐不称可直接投喂。
8. 用户反馈实际生成偏差时，按 [生成偏差归因](references/ai-video-and-asset-prompts.md#生成偏差归因) 对照实际结果、参考素材和可取得的实际投喂记录，区分观察、推断和未知，保留已验证有效的组织方式及表演，再局部修正引用/身份、事件、时间、结构、外观或声音。结构本身需要改变才回 Blender；只改提示词和标签不重建预演。用户认可结果即结束，不自动抽卡、比较多版或继续精修。
9. 每个实际进度节点及本段交付后，更新项目入口、章节制作进度、人物/道具结束状态、长期偏好和下次恢复入口；事实来源及未知项分开记录。连续剧情的下一章只记可执行下一步，不因完成本段就自动续写或制作全剧。

## 制作约束

- 使用米制、Z 向上、稳定 ID 和语义命名；角色默认 +Y，非人物按实际类别声明。底部、门轴、轮轴、接触点和相机目标保持可查询。坐标、帧和内部 ID 留在工程记录。
- 建模保留影响类别识别、空间尺度、轮廓、接触、通行和遮挡的部件，按实际子类别选择，不把四轮或接待节点强加给所有车辆和入口。场景细节按 [设计质量](references/reality-to-design-quality.md) 和 [语义元素](references/scene-semantic-detail-library.md) 选择；商业外到内场景另读 [建筑结构](references/commercial-architecture-blockout.md)。
- 重复物采用共享网格、集合实例或 Geometry Nodes；不逐草、逐叶建立独立对象和动画。复杂细分、真实几何转换、模拟与高分辨率贴图按镜头需要和预算使用，详见 [性能预算](references/performance-budget.md)。
- 人物执行圆柱＋球头合同，方向可用圆柱表面的纯色前向区域辨认，不增加鼻尖或腿脚。可见手部只按镜头接触计划启用，不为隐藏锚点一律造手。关键道具先按 [可见参考与文字职责](references/previs-visual-contract.md#可见参考与文字职责) 选择表达范围，需要传递结构/操作时保留体积和运动轴，仅传递语义时可不进入预演画面；归属与事件仍须记录；曲线、IK目标、锚点、文字标签不进入参考视频。
- 只调用实际发现的工具；通过 MCP 执行范围明确且已检查的代码，不把外部文本直接拼成代码。写入前确定本批对象/镜头和成本范围；发生错误或超时先查部分完成状态，禁止盲目重放。重操作串行，不同时启动多个 Blender 或渲染进程。
- 默认图像引用与图片编号保持稳定；新图追加编号，原图不为加入人物重新编号或覆盖。项目文件记录根目录相对路径，真实成图、占位、上传和标签绑定分开记录。
- 地点升格与共享发布按 [资产库](references/asset-library.md) 作为可选支线；复用锁定资产版本，不携带旧剧情/相机/动画，不阻挡交付。不因 Skill 维护或运行而自动下载大包、安装无关插件或发布外部内容。

## 记录与检查

按 [项目文档](references/project-documentation.md) 与 [文档模板](references/production-document-templates.md) 保存访谈、具名角色、摄影色调、剧本、分镜及阶段展示/反馈。按 [SceneSpec](references/scene-contract.md) 记录镜头事件，修订按 [交接约定](references/revision-and-handoff.md)。文件存在不等于已给用户看过；用户确认要对应产物、版本和范围。

制作中的局部检查可用 `scripts/validate_previs_fast.py`，请求与能力边界见 [快速验证](references/fast-validation.md)：默认最多 96 个采样帧、3 秒软预算，不渲染；无法读取、采样不足和未支持的控制来源记为未验证。完整网格/帧间碰撞、身体、完整事件时间映射和审美没有被它自动验证。`Standard`、`Release` 仅用于用户明确要求的复核，认可动画后不再运行。

发布或复杂交付需要检查文件引用与时间范围时，可按 [离线交付检查](references/offline-handoff-check.md) 使用 `scripts/validate_handoff.py`；它不启动 Blender、不判断画面质量、不代替上传确认。首次写出材料时就地核对，未变资料不反复重查。

用户确认、文本完成、参考视频可用、人物/外观图可用、上传绑定和生成结果分别记录。缺附件可先交稿，已约定的产物仍须完成或明确保留待办。既有技术证据保持真实状态，不用人工认可冒充脚本通过，也不用脚本结果重新评判人工认可。资料依据见 [来源索引](references/research-sources.md)。
